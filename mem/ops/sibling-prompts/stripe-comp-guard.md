# Stripe webhook がコンプのテナントを書き換えないようにしてください

ジムボード（このアプリの元）で実際に起きた事故の移植修正です。

## 何が起きたか

運営自身の店（コンプ = `max_customers IS NULL`・無償で無制限）に、課金テストで
Stripe のサブスクが紐づいていた。そのサブスクの削除イベント
（`customer.subscription.deleted`）を webhook が受けて、コンプの店を **free
（顧客上限5名）へ格下げ**した。顧客数 > 上限になり、**新規予約と記録の作成が全部
止まった**。通知は一切出ず、画面のバナーで発覚した。

## やること（決定済み・変えないこと）

1. Stripe webhook の Edge Function に **isCompTenant ガード**を追加する。
   コンプの定義はこのアプリの既存コード（サブスク判定のヘルパー）と**同じ式**を使う
   （ジムボードは `max_customers IS NULL`。テナントIDの直書きは**しない**）
2. ガードは**プランの適用（作成・更新・checkout 完了）と deleted の格下げの全経路**
   に効かせる。コンプのテナントには一切書かない
3. コンプを本当に課金へ移すときの手順もコメントに書く: 先に max_customers に値を
   入れてコンプを解除してから checkout（ガードで無視されるのは意図どおり）
4. **見張りテスト**: ガードが `update` より**前**にあること・判定の向き
   （NULL がコンプ側）までソースで固定する。変異（ガード削除・向き反転・
   update より後ろへ移動）で赤になることを確認
5. **今すぐ点検**: このアプリの本番でコンプの店に Stripe サブスクが紐づいて
   いないか、既に格下げされていないかを確認する（ジムボードは事故発生後に
   復旧が必要だった）。壊れていたら復旧してから修正を入れる

- Edge Function は push では本番に出ない。マージ後に Lovable のエージェントへ
