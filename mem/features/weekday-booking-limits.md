# 曜日ごとの会員の1日の上限（2026-10-28）

## 要望

宗本さん（設定画面「1日の上限人数」のスクリーンショット。「週に3日まで」を丸で囲んで）:

> これ、曜日ごとに上限設定できる様にもして

意味が分かれるので聞いた。答え:

1. **曜日ごとに会員の人数を決める**（例: 月5・火6・水5・木6・金5・土6・日4）。
   今の「週に何日か、上限を増やす」も**一緒に使える**（曜日の人数より多くできる）
   - ほかの案（「6人にできる曜日を選ぶ」「曜日を絞って週に何日まで」）は選ばれなかった
2. 体験も含めた合計の上限（`daily_total_limit`）は**全曜日同じ**

2026-09-01 には「上限は毎日おなじ1つの数字。曜日で変えたい日は予定表から手で止める」と決めていたが、
この要望で改めた。

## 設定の形

`tenants.daily_booking_limit_weekdays`（jsonb・NULL 可）

```
{"0": 4, "2": 6}     キーは曜日（0=日曜〜6=土曜。operating_hours.days と同じ数え方）
                     キーの無い曜日は daily_booking_limit（共通）
NULL                 全曜日共通（今まで通り）
```

- CHECK: `weekday_limits_valid()`（オブジェクト・キーは "0"〜"6"・値は 1〜99 の整数）
- 🔴 **CHECK から呼ぶ関数なので EXECUTE を外さない。** 外すと店のスタッフが tenants を更新できず、
  設定の保存が全部落ちる（引数しか見ない関数なので、誰が呼んでも害は無い）
- 画面: ジム設定 → 予約のルール → 1日の上限人数 →「曜日ごとに変える」（ON にした店だけ曜日の選択が出る）。
  並びは月曜〜日曜。閉じているときは「共通」だけ出す（スマホの幅で「共通（5人まで）」が切れるため）
- 保存: OFF なら NULL。ON でもどの曜日も「共通」なら NULL。使っていない店（OFF のまま・値も無い）は
  **列に触らない**（今まで通りの書き込み）

## 「週に何日か増やす」との組み合わせ（数え方を改めた）

```
その日の会員の上限 =
  その週（月〜日）の「ほかの日」で、上限を増やした日が weekly_peak_days 日未満 → weekly_peak_limit
  それ以上                                                          → その曜日の上限

上限を増やした日 = 会員が「その曜日の上限」を超えて入った日
                  （曜日の上限が weekly_peak_limit 以上の曜日は増やさない・数えない。上限を外した日も数えない）
```

🔴 **以前（2026-10-22〜）は「weekly_peak_limit 人以上の日」を数えていた。** 改めた理由:

- 曜日ごとに人数が違うと、もともと6人の曜日（火）の6人目を「増やした日」に数え、ほかの曜日の枠を減らす
- 上限4・増やした日6 のように2人以上の差があると、5人の日を数えず、**どの日も5人まで入ってしまっていた**

上限5・増やした日6（1人差。いま設定しているのは御所南だけでこの形）なら、どちらの数え方でも同じ答え。
本番で全ジムの答えが変わらないことを確かめた（下）。

例（共通5・日4・火6、週に3日まで6人）: 月6・火6・水6・日5 → 増やした日は月・水・日の3日
（火はもともと6人なので数えない。日は4人を超えたので数える）→ 木〜土は5人まで。
月を1件取り消すと、増やした日は2日 → 木もまた6人まで。

## 🔴 計算は DB の1か所（今まで通り）

`tenant_member_day_limits` を書き直しただけ。会員のガード（GB007）・カレンダーの受付終了・残り枠は
全部これを使うので、そのまま曜日の上限が効く。画面の写しは `src/lib/weekdayLimits.ts`
（曜日の読み替え）と `src/lib/weeklyPeak.ts`（`memberLimitOn`。予定表の「n/◯人」）。

- 曜日の数え方: DB は `extract(isodow …) % 7`、画面は UTC の `getUTCDay()`（どちらも 0=日曜）
- `get_tenant_daily_limit_left`（残り枠）: 「上限が何も無い店は返さない」に曜日の上限を足し、
  上限の無い日（その曜日も共通も上限なし・合計も無し）は返さないようにした（画面は「無い日＝上限なし」）
- 合計の上限（`tenant_day_total_reached` / 体験予約ページ）は触っていない（全曜日同じ）
