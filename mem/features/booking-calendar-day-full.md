# 満枠の日をカレンダーで押せなくする（お客様の予約画面）

## 何をしているか

会員アプリの予約カレンダーで、**その日に1枠も取れない日**を定休日と同じ見た目
（薄い・押せない）にする。2026-09-20 の宗本さんの要望:

> 撮れる枠が無くなった日にちは薄くして、他みたいにそもそもその日は押せない仕様にして。
> また枠が空いたら予約が取れる様に数字を黒くして日にちを押せる様にして。

- 判定は `src/lib/bookingDayFull.ts` の `isDayFullyBooked`（枠の一覧と「その枠は取れないか」を受け取るだけ）
- 組み立ては `src/components/customer/CustomerBooking.tsx` の `isDayFull`
- 見張りは `src/test/bookingDayFull.test.ts`

**状態を持たない。**「満枠になった日」をどこにも保存せず、描画のたびに数え直す。
キャンセルで1枠空けば、次の描画で自動的に押せる日に戻る（要望の後半そのもの）。

数えるもの … 満枠（同時受入数・担当の重なり・店のブロック枠）／受付しない時間帯
数えないもの … 予約の締切（当日は空き状況を見せる。2026-09-05 の決定）
数えないもの … プランの残り回数（日付ではなく「その人」の事情。数えると回数を
使い切った人のカレンダーが全部灰色になり、空き状況すら見られなくなる）

## 🔴 入れた翌日に「一度も効いていない」ことが分かった（2026-09-21）

> 全ての営業時間にブロック入れていて予約が取れない 10/2 の日にちが
> 押せるようになったままですよ

**判定は正しかった。渡すデータが足りなかった。**

`CustomerBooking` は埋まり枠（`get_tenant_booked_slots`）を
**選んだ日ぶんだけ**読んでいた（`from_date` と `to_date` に同じ日付を渡していた）。
枠グリッドは選んだ日しか見ないのでそれで足りていたが、**カレンダーは数十日ぶんを見る**。
選んでいない日は埋まり枠ゼロ＝「まだ空きがある」と判定され、
全営業時間をブロックした日まで黒いまま押せた。

直し方は、埋まり枠を**予約できる範囲まるごと**（今日 〜 `maxBookableKey`）で1回読むこと。
公開の体験予約ページ（`TrialBooking` の `fetchExistingSlots`）は最初から60日分を
まとめて読んでいたので、読み方をそちらに揃えた形になる。

### 教訓（同じ形を繰り返さないために）

**日をまたいで引く判定には、日をまたいだデータが要る。**
純粋関数の単体テストは全部緑だった（判定は本当に正しいので）。
足りなかったのは「その関数に何を渡しているか」を見るテスト。
`src/test/bookingDayFull.test.ts` に、実際のライブラリを繋いだ組み立ての
テストと、`from_date`/`to_date` が同じ値でないことを見る番犬を足してある。

### 付随して変えたこと

- `src/lib/bookedSlots.ts` に `groupBookedSlotsByDate` / `bookedSlotsOnDate` を追加。
  カレンダーは1回の描画で数十日ぶん引くので、範囲ぜんぶの配列を毎回走査させない。
  判定そのものは変わらない（`isFootprintBlocked` は渡された配列を日付で絞る）。
- `fetchBookedSlots()` は引数を取らなくなった。範囲ぜんぶを読み直すので、
  予約変更のときに「動かす前の日」を別途読み直す必要も無くなった。
- 日付を押し直したときに読み直すのは今までどおり（他の端末が直前に取った枠を拾う）。
