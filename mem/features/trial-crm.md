### 1. 体験の前日リマインドが一度も飛んでいなかった

実データ26件のうち16件がキャンセルになっている。

### 2. フォロー状況が1件も記録されていない

体験予約70件（2026-06-15〜）が**全件「未対応」**、メモ0件。
うち44件はオーナーのテスト予約（`test|example|munekan|kyoto-salute` を含む連絡先）で、
実データは約26件・実質10名ほど。

つまり**画面はあるが使われていない**。中身がテスト予約だらけで
見に行く意味が薄かったのも一因と思われる。

## 🔴 コード化で気をつけたこと

### 公開済みのアプリは日本語を書いてくる

端末に配ったアプリは書き換えられない。CHECK をコードだけにすると、
**古いアプリからの保存が全部落ちる**。

そこで**入口で翻訳する BEFORE トリガー**（`normalize_trial_follow_up_status`）を置いた。
古いアプリは今までどおり動き、DB には常にコードだけが入る。

⚠️ **想定外の値でも例外を投げない**（`pending` に倒す）。
ここで落とすと、店は原因の分からないエラーを見ることになる。

本番で実測（BEGIN…ROLLBACK）:

| 送った値 | 保存された値 |
|---|---|
| 未対応 / 来店した / 入会した / 見送り | pending / visited / joined / declined |
| なにか変な値 | pending |
| joined（新しいコード） | joined |

### ダッシュボードも忘れず直す

`TrainerDashboard.tsx` が `.eq("follow_up_status", "未対応")` でフォロー待ちを数えていた。
ここを直し忘れると、**コード化した瞬間に件数が常に0**になる（静かな劣化）。
見張りで固定してある。

### `trial_fee_status` はまだ日本語

同じ表の `trial_fee_status`（未確認 / 頂いた / 入会のため免除）は日本語のまま。
こちらは元から CHECK があるので値は荒れないが、**隣り合う2列で流儀が違う**。
揃えるなら同じ形（トリガー＋CHECK 差し替え）でできる。今回は範囲を絞って見送った。

## 🔴 project ref を焼き込まない

cron の URL を `https://<ref>.supabase.co/...` と直書きしたら、
既存の見張り（`messageNotification.test.ts`）が捕まえた。

**兄弟アプリがこの migration をコピーした瞬間、そのジムの通知が
ジムボードのプロジェクトへ飛ぶ。** vault の `project_functions_url` から読むこと。

本番の cron も `cron.alter_job` で vault 参照に直した（作った直後は直書きだった）。
