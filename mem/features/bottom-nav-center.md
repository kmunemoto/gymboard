# 下部ナビの予約ボタンを中央に保つ（2026-08-06）

## 何が壊れていたか

全タブを `flex-1` で並べるだけだったので、**タブが偶数個になると丸ボタン（予約）が
構造的に中央に来ない。** N個・i番目（1始まり）の中心は `((i - 1) + 0.5) / N`。

| 記録 | 食事 | 並び | 予約 | 中心 |
|---|---|---|---|---|
| ON | ON | ホーム 記録 [予約] 食事 設定 | 3/5 | 50% ✅ |
| OFF | OFF | ホーム [予約] 設定 | 2/3 | 50% ✅ |
| **ON** | **OFF** | ホーム 記録 [予約] 設定 | 3/4 | **62.5%** ❌ |
| OFF | ON | ホーム [予約] 食事 設定 | 2/4 | **37.5%** ❌ |

**ジムボードは5タブ全ONなので表に出ていなかった。**
ピラボード（記録ON・食事OFF）が実機で発見。画面幅の 12.5%（100px 以上）ズレていた。

旧コメントは「タブが3つでも5つでも自然に幅が分かれる」と書いていた。
**「4つ」が抜けていた。**

## 直し方

左・中央・右の3グループに分け、**左右に同じ flex 係数**を与える。
少ない側は**不可視のスペーサー**で埋めてスロット数を揃える。

**中央も固定幅ではなく `flex: 1`。** 左右が `flex: sideSlots` で中の子が
`flex-1` × sideSlots 個なので、**中央を含む全スロットが等幅**になる。
固定幅（`w-20` 等）にすると中央だけ幅が違う。

つまり3グループとも **「flex 係数 == 子要素数」** が成り立つ。**これが不変条件。**

- **スペーサーは中央側に置く。** 端に置くと隣のタブが中央寄りになり、端が空いて不自然
  （`ホーム 記録 [予約] ␣ 設定` が正しく、`ホーム 記録 [予約] 設定 ␣` は不自然）
- **スペーサーは `button` にしない。** ナビのラベル一覧（`nav button` を数える
  既存検査）に空文字が混ざる
- 5タブなら `sideSlots = 2` でスペーサー0個。**従来と同じ等幅5分割**

## 検査（`src/test/bottomNavCenter.test.tsx`）

jsdom はレイアウトを計算しないので、ピクセルでは測れない。**構造で判定する。**

```
1. 左右のグループの flex 係数が等しい    → 中央グループが真ん中に来る
2. 各グループで「flex 係数 == 子要素数」  → 全スロットが等幅になる
```

### 🔴 2 を省くと検査が素通りする

**ピラボードの敵対的レビューで見つかった穴。** 1 だけを見ると、
**両側を同時に `flex-1` に変える**改変を通してしまう
（予約は中央のままなので目的は満たされて見えるが、中央スロットだけ幅が変わる）。

**最初の変異テストが片側しかずらしていなかったのが見落としの原因。**

変異5種で確認済み（すべて赤）:

| 変異 | 結果 |
|---|---|
| 右グループの flex だけ変える | 赤 6件 |
| **左右を同時に flex:1 にする**（例の穴） | 赤 3件 |
| スペーサーを消す | 赤 3件 |
| 中央を固定幅にする | 赤 4件 |
| スペーサーを button にする | 赤 4件 |

## 検査の書き方で1つ踏んだ

新しいテストの `import "@/i18n"` が存在せず（正しくは `@/lib/i18n`）、
**スイートごと収集に失敗していた。** それでも他ファイルと一緒に流すと
「Tests 7 passed」と出るので、**grep のパターンに `Failed Suites` を含めないと
緑に見える。**

**テストを足したら「増えた件数」を必ず確認すること。**
