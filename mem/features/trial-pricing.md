# 体験を「無料」からジムごとの料金へ（2026-08-08）

Salute御所南が体験を有料に切り替えた。

```
体験トレーニング      ¥3,000（税込）
当日に入会した        ¥0（頂かない）
当日に入会しなかった   ¥3,000 を当日いただく
```

---

## 🔴 これは1ジムの都合。全ジムの仕様ではない

本番には**15テナント**いる。無料体験で集客しているジムもありうるので、
**金額をコードに書かない。** `tenants.trial_price_yen` に持つ
（CLAUDE.md「特定テナント専用の変更を全テナントに適用しない」）。

マイグレーションは**入れ物だけ**を作り、Salute の 3000 は本番で個別に入れた。
`src/test/trialPricing.test.ts` が「マイグレーションが金額を UPDATE していないこと」を見張る。

## `null` と `0` は別物

```
null … 料金の設定なし。**何も表示しない**（従来どおりの見た目）
0    … ジムが「¥0」と明示した。**「¥0」と表示する**
```

`if (!price)` と書くと 0 が落ちる。**必ず `hasTrialPrice()` を通すこと。**
`src/lib/trialPricing.ts` と `supabase/functions/_shared/trial-pricing.ts` に同じ判断を置いてある
（片方だけ直すと「画面には出るのにメールに出ない」が起きるので、検査で両方の存在を突き合わせている）。

---

## 「無料」の文言は、もともと Salute だけに出ていた

`isFreeTrial`（= `tenantId === SALUTE_TENANT_ID`）で分岐しており、他14ジムは最初から
「体験」表記だった。**今回直したのは実質 Salute の分だけ。**

呼称は全ジム共通で**「体験トレーニング」**に揃えた。料金を語らない呼称なので他ジムに実害は無い。

### 🔴 `isFreeTrial` は二役を兼ねていた

```
supabase/functions/_shared/transactional-email-templates/trial-booking-reminder.tsx
  {isFreeTrial && (   ← 「手ぶらでOK・ウェア無料レンタル・お水あり」のブロック
```

このフラグは「無料と呼ぶ」だけでなく、**Salute の設備案内を出すかどうかも兼ねていた。**
素直に消すと、**リマインドメールから手ぶらOKの案内が黙って消える**ところだった
（宗本さんが「変更しないもの」として明記していた項目）。

料金（`trialPriceYen`）と設備案内（`showAmenities`）に**分けた。**
検査で「設備案内のブロックが残っていて中身が空でない」ことを見張っている。

> **文言そのものは断言していない。** このメールテンプレートは i18n を通さない日本語直書きで、
> フォークは自分のジムの設備に書き換える。リテラルで固定すると正しく書き換えたフォークで落ちる
> （`forkHostileTests.test.ts` が実際に検出した）。構造で見ること。

---

## 🔴 DBの値 `'初回無料体験'` は改名していない

これは**表示文字列ではなく内部キー**。`bookings.booking_type` の既定値で、突き合わせに使われている。

```
PlanUsageCard.tsx        EXCLUDED_PLAN_NAMES
CustomerHome.tsx         hasPlan の判定
CustomerMonthlyReport    同上
planSlotDuration         プラン別の所要時間
```

改名すると**既存行と突き合わなくなり、エラーも出ないまま挙動が変わる。**
表示ラベルだけ変える方針は `CustomerBooking.tsx:54` で以前から採っているのと同じ。
検査でキーの現存を見張っている。

---

## 🔴 `get_tenant_public` に列を足すと ACL が飛ぶ

戻り値の型が変わるので `CREATE OR REPLACE` では通らない（`cannot change return type`）。
**`DROP` してから作り直すことになり、その瞬間に ACL が消える。**

この関数は**未ログインの体験予約ページが呼ぶ3関数のうちの1つ**で、
anon の EXECUTE が落ちると**予約ページが真っ白になる。**

```sql
DROP FUNCTION IF EXISTS public.get_tenant_public(uuid);
CREATE FUNCTION public.get_tenant_public(p_id uuid) ...
GRANT EXECUTE ON FUNCTION public.get_tenant_public(uuid) TO anon, authenticated;  -- ★消さない
```

検査で「DROP より後に anon への GRANT があること」を見張っている。

**適用後は `has_function_privilege` で満足しないこと。** 実際にロールを演じて読む
（`mem/ops/tenant-boundary.md` 穴8で、それを怠って本番を落としている）。

```sql
BEGIN;
SET LOCAL ROLE anon;
SELECT gym_name, trial_price_yen FROM public.get_tenant_public('<tenant>'::uuid);
ROLLBACK;
```

## 当日決済は「記録だけ」

**アプリは決済しない。** 現金・カード・QR はこれまでどおり店頭の手段で受け取る。

ジムがお客様からお金を受け取る仕組みは、このアプリには**一切無い**
（Stripe はジムがジムボードに月額を払う用だけ）。入れるなら Stripe Terminal / Connect の
導入になり、ジムごとの加盟店審査・本人確認・手数料設計が絡む別プロジェクト。

代わりに `trial_bookings.trial_fee_status`（`未確認` / `頂いた` / `入会のため免除`）を
体験フォロー画面から記録できるようにした。**料金を設定しているジムにだけ欄が出る。**
「アプリでは決済しません」と画面にも1行出している（誤解を招かないため）。

---

## 「当日入会なら無料」はどこに書くか

**金額欄では表現できない。** `tenants.trial_info_body`（ジムが編集できる案内文）に書く。
Salute の本番値は下記（体験予約ページの案内カードにそのまま出る）。

```
体験トレーニングの料金は¥3,000（税込）です。
体験当日にご入会いただいた場合は、体験料は頂戴しません（¥0）。
体験当日にご入会されない場合のみ、¥3,000を当日お支払いいただきます。

初めての方限定の体験です。ウェア・シューズの無料レンタル、お水のご用意もあるので手ぶらでOK。
プロのトレーナーがマンツーマンで、目標や体力に合わせて丁寧にサポートいたします。
```

> **お客様に見える「無料」は、コードではなく本番データ側にあった。**
> 変更前の Salute は `trial_info_title = '初回無料・手ぶらでOK'` /
> `trial_info_body` の1行目が「初めての方限定の無料体験です。」だった。
> **コードだけ直しても、ここが残っていれば予約ページには「無料」と出続ける。**

# キャンセルポリシー（2026-08-08・同日）

Salute御所南がキャンセルポリシーも変えた。

```
予約の変更・キャンセルは、アプリからいつでも可能
当日のキャンセルでも、キャンセル料やセッションの消費は一切なし
連絡なしの無断キャンセルでも、ペナルティなし
```

## 🔴 「解除する設定」はほとんど無かった

依頼は「ペナルティなしに変更して。キャンセル期限やキャンセル料が入っていれば解除して」だったが、
**実装を調べたら、解除すべきものがほぼ無かった。**

| | 実態 |
|---|---|
| キャンセル料の仕組み | **存在しない** |
| キャンセル期限の仕組み | **存在しない**（キャンセルはいつでも可能） |
| 無断キャンセルの仕組み | **存在しない** |
| 当日キャンセルの消化扱い | `tenants.same_day_cancel_penalty_enabled` で切替可。**Salute はもともと false** |

**挙動は既に希望どおりだった。** 足りなかったのは「そうだとお客様に伝える場所」で、
キャンセル画面には「予約をキャンセルしますか？」としか出ていなかった。

## ⚠️ 「前日まで」は予約の締切であって、キャンセル期限ではない

コード中の「前日まで」は `tenants.booking_cutoff_type` / `booking_cutoff_hours`＝
**いつまでに予約できるか**の設定。**キャンセルの話と混ぜて消さないこと**
（消すと当日予約が通るようになる）。今回は触っていない。
`src/test/cancelPolicy.test.ts` が「キャンセルの変更で booking_cutoff を触っていない」を見張る。

## ペナルティが ON だったのは審査用デモだけだった

本番15テナントを実測したところ、`same_day_cancel_penalty_enabled = true` は
**「ジムボードパーソナルジム」1件だけ**だった。

```
オーナー = munekan2989+review@gmail.com   ← ストア審査用のアカウント
status   = active / 直近30日で101件の予約
```

宗本さんの確認のうえ OFF にした。**現在 ON のジムは0件。**

> ⚠️ Salute御所南は `status = 'trial'` のまま（34名・385予約）。
> 審査用デモのほうが `active`。**紛らわしいので、どちらを触るか毎回確認すること。**
> `gym_name` だけで判断しない（同名の空テナント `98453697…` も存在する）。

## 追加したもの: `tenants.cancel_policy_body`

**既定文を持たせない。** ペナルティの有無は店ごとに違うので、上流が代弁すると事実と食い違う。
空欄なら**何も表示しない**（従来どおりの見た目）。

| 出す場所 | 理由 |
|---|---|
| お客様の予約画面 | **予約する前**に読める |
| キャンセル確認ダイアログ | **キャンセルする瞬間**に読める |

ペナルティの警告（`forfeitPending`）を出しているジムでは、そちらを優先する
（「1回分消化になります」と「ペナルティはありません」が同時に出ると矛盾するため）。

Salute の本番値:

```
・予約の変更・キャンセルは、アプリからいつでも可能です。
・当日のキャンセルでも、キャンセル料やセッションの消費は一切ありません。
・ご連絡なしのキャンセルの場合も、ペナルティはありません。
```
