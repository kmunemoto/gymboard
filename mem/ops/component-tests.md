# コンポーネント描画テスト

## 🔴 変異検証のあとは vite のキャッシュを消す（2026-08-12）

**変異検証の直後に1回だけテストが落ち、そのあと32回走らせても再現しない**、
という現象を踏んだ。原因は製品コードではなく**検証のやり方**だった。

`node_modules/.vite` の変換キャッシュは **mtime と サイズ**で効く。変異検証は

```
ファイルを書き換える → テスト → cp でバックアップから戻す
```

を繰り返すが、このとき

- 戻すのが**同じ秒のうち**（mtime の粒度は1秒）
- 変異が**バイト数を変えない**（`return -1` ↔ `return 1` の入れ替え等）

の両方が重なると、**戻したはずのファイルに対して変異版のキャッシュが使われる**。
次に走らせたテストが、ソースは正しいのに変異版の挙動で落ちる。

実際に踏んだのは `conversationOrder.ts` の比較を反転させる変異で、
元と変異版が**どちらもちょうど 1700 バイト**だった。落ちたテストは1件で、
その変異が落とすテストとぴったり一致した。

```bash
# 変異検証の締めに必ず
rm -rf node_modules/.vite
```

⚠️ **「再現しない謎のフレーク」で片付けないこと。** CLAUDE.md にあるとおり、
同じ判断で2026-08-12 に一度 CI を落としている。再現しないときは
**なぜ再現しないのかの説明**（今回はキャッシュ）まで辿ること。
説明がつかないうちは緑を信用しない。

## 書くときの注意

### 言語は ja に固定されている

`src/test/setup.ts` で `localStorage.setItem("i18nextLng", "ja")` している。これが無いと
jsdom の `navigator.language`（en-US）で英語が選ばれ、さらに `@/lib/i18n` の
「保存言語を後から読み込んで再適用する」非同期処理がテスト実行中に割り込んで、
**同じテストが実行タイミングで通ったり落ちたりする**（実際に8回中1回落ちた）。

### jsdom は CSS を評価しない

`hidden md:flex` などで出し分けているデスクトップ用とモバイル用は、**両方DOMに出る**。
`TrainerSidebar` はラベルが異なる（例: ダッシュボード / ホーム）ので、それぞれで確認している。

### Radix のアコーディオンは閉じている間、中身をDOMに出さない

`TrainerGymSettings` は一度カテゴリー別アコーディオンに再編したが、オーナーの意向で撤回し
1本の縦並びリストに戻した（2026-07-26）。そのため今は開閉操作なしで全トグルが見える。
`TrainerHelpGuide` など、他の画面でアコーディオンを使う場合はこの注意が引き続き当てはまる
（閉じている間は中身をDOMに出さないので、先にトリガーをクリックして開く）。

### Supabase を叩く子コンポーネントはスタブにする

画面構造の検証が目的なら、`TrainerPlanManager` などはスタブに差し替えてよい。
ただし**検証対象そのもの**（招待コードカードの配置など）は、位置が分かる目印に置き換える。

### モックが本物の壊れ方を再現できているか確かめる

`realtimeChannelCollision.test.tsx` には「固定名を使うと確かに throw する」ことを
確認するテストを入れてある。これが無いと、モックが甘くなったとき
残りのテストが「何も検証していないのに緑」になる。

### 追加したら変異テストで確認する

実装をわざと壊してテストが落ちることを確認してから入れている。落ちないテストは
書いていないのと同じ。実際にこの方法で、純粋関数テストでは捕まえられない回帰
（開いているタブを残す例外）が1件あることが分かった。
