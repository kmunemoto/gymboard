# 「ご来店は 13:55 以降にお願いします」（2026-10-10）

## 要望

宗本さん:

> 予約を受けた時にお客様にセッション開始の5分前以内にお越しください。のメッセージを伝えたい。
> 10分前とかに来られると困るから。

## 見せ方（案を出して「1と2だけ実装」と決まった形）

- **その予約の開始時刻から計算した時刻**で出す。14:00 開始・5分前なら
  **「ご来店は 13:55 以降にお願いします」**＋理由の一文「前のセッション中のため、早めのご来店はご遠慮ください」。
  「5分前以内に」とだけ書くとお客様が引き算をすることになり、読み流されやすいため
- 出す場所（`src/components/booking/ArrivalNotice.tsx`）:

| 場所 | 出し方 |
|---|---|
| 会員の予約完了画面（`BookingCompleteDialog`） | 日時のすぐ下。時刻＋理由 |
| 会員のホーム「次回の予約」（`CustomerHome`） | カードの下。時刻だけ（`compact`。理由は予約完了画面で出している） |
| 体験予約の完了画面（`TrialBooking`。未ログイン） | 日時のすぐ下。時刻＋理由 |

- **メール・通知（前日 21 時の「明日のご予約」など）には入れていない。** サーバー側（Edge Function・
  メールテンプレート）の変更になり、本番へ出すには Lovable に頼む必要があるため、今回は見送った
  （宗本さん「1と2だけ」）。入れるなら `push-booking-reminder`（通知本文）と
  `booking-confirmation` / `booking-reminder` / `trial-booking-confirmation` テンプレートの3系統。
  **それまでの代わり**: 予約確認メール・前日メールには店ごとの一文欄（`booking_email_note` /
  `reminder_email_note`。設定 → メール・通知）が既にあるので、そこに文を入れれば今日からメールにも載る
- ドロップイン予約（訪日客向けの別ページ）にも入れていない

## 店ごとの設定

`tenants.arrival_lead_minutes`（integer・NULL 可。CHECK は 1〜60）。
設定 → 予約のルール →「来店の目安時刻をお客様に案内する」（`ArrivalLeadCard`。選択肢は 3/5/10/15/20/30 分）。

- 🔴 **既定は NULL＝何も出さない。** 他のジムの見え方は変わらない。上流が文言・分数を代弁しない
  （`cancel_policy_body` と同じ方針）
- 🔴 **特定のジムの値は migration に書かない**（リポジトリは public）。本番で直接設定する
- 列が読めない環境（migration 未適用）は `tenantColumns.ts` で null に倒す＝出さない
- 設定カードの下に「例）14:00 開始の予約 →「ご来店は 13:55 以降にお願いします」」の見本が出る
  （保存前でも、お客様に何と出るかが分かる）

## 仕組み

- 計算: `src/lib/arrivalGuide.ts` の `arrivalFromTime(開始時刻, 分)`。**日をまたがない**
  （0:03 開始・5分前でも 00:00。前日の 23:58 にしない）。範囲外・整数でない・開始時刻が読めない → null
- 体験予約ページはログイン不要で `tenants` を読めないので、**`get_tenant_public` に列を足した**
  （`20261010010000_arrival_lead_minutes.sql`。返り値の型が変わるので DROP → CREATE → **GRANT の貼り直し**
  の3点セット。anon に GRANT を戻し忘れると体験予約ページが全店で開けなくなる）
- 会員側は `useTenant()` の店情報（`select` の対象列に追加済み）。`CustomerBooking.tsx` は行数の上限
  （`qualityRatchet.test.ts`）に達しているので触らず、**ダイアログ側で `useTenant()` を読む**形にした
- `TrainerGymSettings.tsx` も上限ぎりぎり（1600 行・いま 1600）。**これ以上は足さず**、足すなら別ファイルへ
