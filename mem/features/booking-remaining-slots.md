# お客様の予約カレンダーに「残り枠」を出す（2026-10-06）

## 要望

宗本さん（会員アプリの予約画面のスクリーンショット）:

> お客様側の予約サイトで各日にちが残り何枠空いているかリアルタイムで表示される機能を追加して
> 表示の仕方をいい案考えて

## 見せ方

| 日付の下 | いつ |
|---|---|
| 「残N」（控えめな色） | 空きがある日 |
| 「残N」（目立つ色・太字） | 残り `FEW_REMAINING_SLOTS`（2）以下 |
| 「満」 | 満枠で押せない日（キャンセルが出れば戻る） |
| 何も出さない | 定休日・受付終了・予約できる範囲の外・当日で締切後 |

- カレンダーの下に一行の説明（「残○」はその日にまだ予約できる回数です（自動更新））
- 残りを出すときだけマスを 36px → 44px に（日付と「残N」を縦に並べる。指でも押しやすい）
- 選択中・今日のマス（背景に色）では目立つ色にしない（色の上に色で読めない）
- 自分の予約がある日の丸印は今まで通り

## 🔴 「枠」は開始時刻の数ではない

開始時刻は **15分刻み**（`staffBookingSlotMinutes`）。御所南（10:00〜22:30・60分）は1日47通り。
これを数えると「残47」になる。数えるのは **その日あと何回入れられるか**:
朝から順に、取れる最初の時刻に1回ぶん（1枠＋間）を置き、置いたものも埋まりとして次を探す
（`src/lib/dayRemainingSlots.ts` の `countRemainingSlots`）。
同時に1人の店ではこれが最大の回数になる（同じ長さの予定を早い順に詰めるのが最適）。
予約なしの御所南で **10**、14:00 に1件入ると **9**。

判定の式は持たず、枠一覧と同じ `isFootprintBlocked`・同じ開始時刻・受付しない帯・締切を使う。
テストで「0 ⇔ カレンダーの満（`isDayFullyBooked`）」を300通りの埋まり方で突き合わせている。

その人の事情（予約回数の制限・プランの残り回数）は数えない（`bookingDayFull.ts` と同じ理由）。

## 🔴 1日の上限人数も効かせる（2026-10-06 追加）

宗本さん「僕のジムの場合、一日4枠までって制限掛けてるので、その設定は考慮しないと」。
最初の版は時間だけで数えていたので、上限4の店で「残7」と出ていた。

**残り = min(時間に入る回数, 上限 − その日の会員予約の件数)**

- 件数は DB の `get_tenant_daily_limit_left`（新規）が返す。中で
  **`tenant_day_booking_count`＝上限で閉めるガード（GB007）と同じ関数**を使う。
  画面で数え直すと、体験（数えない）・当日キャンセル消化（数える）の扱いがズレる
- 上限を外した日（`booking_uncapped_days`）は返さない＝時間だけで数える
- 🔴 **自分が所属しているジムだけ**返す（`is_tenant_member`）。未ログインは先に弾く。anon に EXECUTE なし
- 上限に達した日は、受付終了の一覧（`get_tenant_closed_days`、`manual=false`）で閉まる。
  カレンダーの理由を `limitReached` として分け、**「満」**を出す（手で閉めた日は今まで通り何も出さない）
- 読み直しは埋まり枠の読み直しに乗る（`useDailyLimitLeft` が埋まり枠の変化で読み直し、
  受付終了の一覧も一緒に読み直す）。設定 OFF の店では問い合わせない
- 読めなければ上限で絞らない（上限に達した日は受付終了の一覧が閉じるので、取れない日に数字は出ない）

本番（2026-10-06）: 関数を適用。御所南の会員として 10/13=3・10/15=2・10/17=2（4−件数と一致）、
他のジムの会員は0行、anon は EXECUTE なしを確認。
見張り `src/test/dailyLimitLeft.test.tsx`（10件）、変異4件（上限を見ない／上限の日に「満」を出さない／
anon に渡す／OFF でも問い合わせる）がすべて赤。

## ほぼリアルタイム

お客様の端末は、他のお客様の予約を Realtime で受け取れない（RLS）。そこで
`src/hooks/useLiveRefresh.ts` が、**開いている間・見えている間だけ1分ごと**に埋まり枠を読み直し、
アプリに戻った瞬間にも1回読む。隠れている間は読まない（問い合わせ＝バックエンドの利用量＝クレジット）。

## ジムごとの設定（既定 OFF）

`tenants.show_remaining_slots`（boolean・NOT NULL・既定 false）。空き具合はジムの混み具合そのものなので、
見せるかはジムが決める。設定画面の「予約」の並び（1日の上限人数の下）に `RemainingSlotsCard`。
**OFF の店は見た目も読み直しも今まで通り**。

### 本番（2026-10-06 適用済み）

- 列を追加。**御所南だけ ON**（ジムの ID と値はマイグレーションに書かず、本番で直接）。他の20ジムは OFF
- 御所南の会員として、設定が true で読めること・埋まり枠の RPC が読めること（翌1ヶ月で58件）を確認
