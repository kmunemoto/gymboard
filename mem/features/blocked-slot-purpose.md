## 器はもうあった

## 🔴 いちばん大事なのは RLS のほう

**「画面に出さない」だけでは「お客様には見せません」にならない。**

適用前、`blocked_slots` には PERMISSIVE な SELECT ポリシー
`Customers can view blocked slots`（`USING (true)`）が付いていて、
**同じジムの会員が REST API で全列読めた**。画面に出していなかっただけ。
用事名は私的な用事や第三者の名前を書く欄なので、ここを塞がないと嘘になる。

本番でお客様ご本人を演じて確認した（適用前）:

```
BEFORE 直読み=15 件 / うち reason 有り=15 件 / 空き枠RPC=80 件
```

### 塞いでも壊れないと言い切れた根拠（適用前に確認）

1. お客様の空き枠は **SECURITY DEFINER の RPC**（`get_tenant_booked_slots` /
   `get_booked_slots`）から取っていて **RLS を通らない**。返す列は
   `booking_date / end_booking_date / status (/ staff_user_id)` だけで **`reason` は無い**
2. `blocked_slots` を直接読むクライアントは `useAllBookings` の1か所だけ。
   呼び出し元は `src/components/trainer/` の3画面のみ
   （予定表・ダッシュボード・稼働率ヒートマップ）。**お客様の画面からは1つも呼ばれていない**
3. 🔴 **全19ジムのオーナー・スタッフ全員が `user_roles` に `trainer` を持っている**。
   1人でも欠けていたら、残る `Trainers can view blocked slots` に引っかからず
   **その人の予定表が真っ白**になっていた（2026-08-06 に本番の全画面を落とした件と同じ形）

### 適用後（ロールを演じて実測）

```
AFTER(お客様)   直読み=0 件（前は15）  / 空き枠RPC=80 件（前は80）  ← 塞がった・壊れていない
AFTER(オーナー) 読めた=15 件（前は15） / 自動生成の reason=0 件      ← 店側は無事・掃除済み
PROBE_OK  用事名「面談」で保存できた／NULL も自動生成19文字も通る／31文字は弾かれる
```

## 🔴 古いアプリは、いまも自動生成 reason を書き続ける

この機能より前の版（iOS 1.6.9 も Android の現行版も）は、`reason` に
「ブロック（14:15〜15:15）」を**必ず**入れる。更新されるまで止まらない。

そのまま用事名として出すと、狭いマスで「ブロ…」になり **いまより読めなくなる**。
なので表示の手前で1枚かませてある: `src/lib/blockPurpose.ts` の `blockPurposeName()`。

**文言ではなく「形」で判定する**（5言語ぶんあるので、どれを直しても外れないように）:

```
^\S{1,12}\s*[（(]\s*\d{1,2}:\d{2}\s*[〜~–—-]\s*\d{1,2}:\d{2}\s*[)）]$
```

⚠️ 「時刻を含む」ではなく**丸ごとこの形**で見る。前者だと「掃除 10:00〜11:00」のような
人の入力まで消す。それでも「掃除（10:00〜11:00）」と括弧付きで書かれると誤判定するが、
そのときは既定の「ブロック」表示に戻るだけで、DB の文字列は残る（打ち直せば直る）。

**DB を1回掃除するだけでは足りない。** 掃除したそばから古い端末が書き足す。

## 🔴 入力欄は20文字、DB の CHECK は30。わざと違う

古いアプリが書く自動生成文字列は英語で **19文字**（`Block (14:15–15:15)`）。
DB を20にすると、**文言を1文字足しただけで古い端末のブロック作成が黙って失敗する**。
出荷済みの版に対して DB 側を厳しくしない。

## 既知の借金

- **`blocked_slots` に UPDATE ポリシーが無い。** つまり
  **用事名は後から直せない**（解除して入れ直すことになる）。
  直せるようにするなら UPDATE ポリシーを足す別の作業が要る
- 週タイムラインは8文字で切る。全文が読めるのは**解除ダイアログとスマホのカード**だけ
- くり返しブロックは**全部の週に同じ用事名**が入る（`recurrence_group` と意味が揃うので、
  これは仕様として正しいと判断した）
