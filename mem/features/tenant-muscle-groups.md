# 部位（トレーニング部位バランス・種目管理）のジムごと編集機能

## 背景
「部位にお尻を追加して」という依頼から、部位一覧（胸・背中・肩・脚・二頭筋・三頭筋・腹筋）が
2箇所（`MuscleBalanceRadar.tsx`・`TrainerExerciseManager.tsx`）に別々にハードコードされており、
そもそも「お尻」を追加する手段が無いことが判明。ジムごとに部位（名前・追加・削除）を
編集できるようにし、変更がレーダーチャート・種目管理の両方に反映されるようにした。

## データモデル
新テーブル `tenant_muscle_groups`（`tenant_id`, `name`, `sort_order`）。
- RLS: SELECT はテナントメンバー全員（お客様のレーダーチャート表示に必要）。
  INSERT/UPDATE/DELETE はトレーナー/オーナーのみ（`exercises` と同じ `has_role` パターン）。
- 既存テナントは migration `20260723080000` で「胸・背中・肩・脚・**お尻**・二頭筋・三頭筋・腹筋」を
  バックフィル済み（既存の見た目・挙動は変わらず、お尻が増えるだけ）。
- 新規テナントは `Onboarding.tsx` の `handleComplete` で同じ既定値を都度シードする
  （`tenant_plans` の直後）。シード失敗はオンボーディング自体を止めない（ログのみ）。
- 「その他」は種目管理専用の常設カテゴリで `tenant_muscle_groups` には**含めない**
  （未分類・削除された部位の受け皿。レーダーチャート側は元々「その他」を軸に出さない設計）。

## 読み込み・キャッシュ
`src/lib/tenantMuscleGroups.ts`。`muscleGroup.ts`（種目→部位マップ）と同じ
モジュール単位キャッシュ + `listeners` の購読パターン。RLSが呼び出し元のテナントに
自動的に絞り込むため、クライアント側で `tenant_id` を明示的に渡す必要はない。
`loadTenantMuscleGroups(true)` で強制再取得（追加・改名・削除の直後に呼ぶ）。

## 反映箇所
- `MuscleBalanceRadar.tsx`（お客様のレーダーチャート）: 軸をハードコードの
  `MUSCLE_GROUPS` からこのテーブル由来の動的リストに変更。
  **落とし穴**: モジュール単位キャッシュは参照が変わらないため、`subscribeTenantMuscleGroups`
  のコールバックだけで再レンダーしても `useMemo`（依存配列ベース）は再計算されない。
  `groupVersion` というカウンタを state に持たせ、購読コールバックで `+1` して
  `useMemo` の依存配列に含めることで確実に再計算させている（`muscleGroup.ts` 側の
  種目→部位マップの購読にも同じ問題があったため、あわせて修正）。
- `TrainerExerciseManager.tsx`（種目管理のフィルタ・追加/編集フォームの「部位」選択肢）:
  同じテーブルを購読。表示上は動的リストの末尾に固定で「その他」を追加する
  （`OTHER_GROUP` 定数、DBには保存しない）。
- `TrainerMuscleGroupManager.tsx`（新規）: 部位の追加・改名・削除シート。
  種目管理画面の絞り込みチップ列に「部位を編集」ボタンで開く。
  - **改名**: `tenant_muscle_groups.name` を更新後、その部位を使っている既存の
    `exercises.muscle_group` / `category` もまとめて新名称に追従させる（カスケード）。
    しないと過去に登録した種目が「宙に浮いた」古い部位名のまま残ってしまう。
  - **削除**: 削除前に、その部位を使っている `exercises` の件数を数えて確認ダイアログに
    表示。1件以上あれば、削除と同時にそれらの種目を `muscle_group`/`category` ともに
    「その他」へ一括で付け替える（付け替えないと種目管理の一覧から見えなくなる
    ＝データは残るが実質迷子になる不具合を生むため）。

## 落とし穴
- `src/lib/muscleGroup.ts`（種目名→部位のフォールバックマップ、翻訳キー）に
  `"お尻": "glutes"` を追加済み。`src/lib/muscleMapIcon.ts`（部位→アイコン画像の
  マッピング）は元々 `"お尻"`/`"臀部"` を認識済みだったため無改修（ジムが独自の部位名を
  追加した場合はアイコンが無く `null` を返すのみ＝既存の全部位共通の既知の制限で、
  今回のスコープ外）。
- 部位名・翻訳の多言語対応は「胸」「背中」等の**既定8種のみ** `muscleGroups.*`（5言語）で
  翻訳される。ジムが独自に追加した部位名（自由入力）はそのまま（未翻訳）で表示される
  （種目名と同じ、ユーザー生成コンテンツのため翻訳しない設計）。
