## 🔴 なぜ「コードを戻すだけ」では足りなかったか

この機能は**DB側が先に効く**作りになっている（画面を迂回されても入らないように、
`trial_bookings` に BEFORE INSERT トリガーを置いていた）。
そのため main を戻すだけでは、**体験予約サイトから送っても弾かれたまま**で、
しかも案内画面は出ないので、お客様には一般的なエラーしか見えない状態になる。
**コードとDBの両方を戻して初めて「保留」になる。**

戻すときも同じで、**片方だけ入れない**こと（下記の順番どおりに）。

## 時が来たら（3つとも要る）

```
1. コードを戻す
   git revert <この取り消しコミット>   → PR → CI緑 → squash-merge
   （この memo も一緒に消える。それでよい）

2. 本番DBに migration を流す
   supabase/migrations/20260919010000_trial_app_only_names.sql
   Lovable の query_database から（Supabase コネクタは permission denied）。
   流したあと 3段構えで実測すること（手順は復活する mem/features/trial-app-only-names.md）

3. Lovable で Publish する
   /trial の案内画面はここで初めて出る
```

そのうえで **お名前の単語を登録する**。
