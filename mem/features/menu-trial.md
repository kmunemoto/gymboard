# メニューの体験予約ページ（マシンピラティス専用の体験予約・2026-10-31）

## 要望

宗本さん:

> マシンピラティス専用の体験予約受付サイトをつくってほしい。
> マシンピラティスの時間の枠だけが表示されるように

聞いて決めたこと（2026-10-31）:

1. **料金はトレーニングと同じ**（¥3,000・当日入会なら無料）。料金・案内文は**メニューごと**に持つ
   （トレーニングの体験の案内文は「体験トレーニングの料金は…」なので流用しない）
2. **受付期間は「今から受け付ける」**: 開始日（starts_on）がまだ先のメニューは、開始日の前日を「今日」とみなして
   「何日先まで」を数える（10日先までの店なら、開始日 11/25 → 11/25〜12/4 を今から予約できる）。
   始まった後はトレーニングの体験と同じ（今日から10日先まで）
3. **案内文は下書きを本番に入れる**（宗本さんがあとで設定から直す）

## 🔴 メニューの体験は「担当のいるメニューの予約」と同じ扱い

| | トレーニングの体験 | メニューの体験 |
|---|---|---|
| 出す枠 | 営業時間 | 担当のシフト ∩ 営業時間（シフトの無い担当は営業時間どおり） |
| 専用の時間（`guard_trial_menu_reserved`） | 入れない | 入れる（担当の時間なので） |
| 担当のシフト（`apply_trial_menu`・GB002） | 見ない | シフトの中に始まること |
| 担当の重なり（`check_booking_overlap`・GB001） | 見ない | 見る（先生は同時に2人を見られない） |
| 時間ブロック | 「体験だけブロックを無視」の設定しだい | **いつも効く**（先生のお休みを時間ブロックで塞ぐため） |
| 開始日より前 | — | 受けない（GB012） |

- 担当は `apply_trial_menu`（BEFORE INSERT）がメニューから入れる。送ってきた値は使わない。
  🔴 **トリガーは名前の順に動く**。重なりの検査（`prevent_trial_booking_overlap`）より先に動く名前にしてある。
  後ろに回すと担当なしで重なりを見る＝先生の二重予約
- 会員の予約画面（担当のいるメニュー）が先生の体験と重ならないよう、`get_tenant_booked_slots` の
  体験の行にも担当を返す（同時受入数が2以上の店で効く。本番は全店1なので今は容量で止まる）
- 未ログインの公開ページには、専用の時間（担当つきのブロック）と普通の時間ブロックの見分けがつかない
  （担当の user_id を返していない）。だからメニューの体験は専用の RPC（`get_menu_trial_slots`）で読む。
  「シフトと同じ時間のブロックを無視する」で代用しないこと（先生のお休みを丸ごと塞いだブロックまで消える）

## 通知

| | オーナー | 担当（先生） |
|---|---|---|
| 予約が入った | メール・プッシュ（・LINE） | メール（`trial-notify-…-staff`）・プッシュ |
| 店が取り消した | オーナー以外が取り消したらプッシュ・メール | プッシュ・メール（`notifyTrialCancelled`） |

- 呼び方は「マシンピラティスの体験予約」（店宛て）／「マシンピラティスの体験」（お客様のメール）。`trialRules.ts`
- 🔴 先生へのメールのキーは代表のキー（`booking-notify-<id>` / `cancel-trainer-<id>`）と別の形にする。
  代表のキーだと send-transactional-email が「古いアプリの誤送信」とみなして代表に送り直す（`staffRouting.ts`）
- トレーニングの体験の取り消しは、オーナーが取り消したなら今まで通り誰にも送らない

## ついでに直したもの（trial-book の開始時刻）

2026-10-31 まで trial-book は「10:00〜21:00 開始・15分刻み」を直書きしていた。画面は営業時間から枠を並べるので、
**22:30 閉店の宗本さんのジムでは 21:15・21:30 の枠が出るのに、送ると「選択できない時間帯です」で断られていた**
（本番の体験予約に 21:00 より後の開始は1件も無かった）。営業時間（メニューの体験は担当のシフト）で見るよう直した。
「何日先まで」も店の設定（booking_window_days）を読むようにした（未設定は今まで通り10日・余裕2日）。

⚠️ **ドロップイン（drop-in-book）は直していない**（同じ 10:00〜21:00 の直書きが残っている）。

### 本番へ適用した記録（2026-10-31）

3段構え。マイグレーションはマージ前に適用（関数7本の本体がリポジトリと一致することを md5 で確認）。

```
1. 試し流し（最後に RAISE で全部戻す）。受付・拒否が設計どおり:
   メニューの体験（11/25 18:00）= 受付・担当は先生（送った担当は無視）
   開始日より前 = GB012 / 木曜（シフトなし）= GB002 / 水曜 15:00（シフト前）= GB002
   トレーニングの体験を専用の時間に = 断る / 先生の体験と重なる（同時受入数1）= 断る
   同時受入数2でも先生の重なり = GB001 / ドロップインにメニュー = GB012
   別のジム = GB012 / 体験オフ = GB012 / トレーニングの体験に担当を送る = 担当は NULL
   時間ブロック ×「体験だけ無視」ON: メニューの体験 = 断る・トレーニングの体験 = 受付
2. 適用 → 未ログイン・お客様を演じて get_tenant_public / get_tenant_booked_slots / メニューを読める
3. Edge Function 4本を Lovable でデプロイ → trial-book を DB から叩いて新しい判定を確認
   （メニューの指定が壊れている・体験オフ・開始日より前・シフト外・期間外。どれも予約は作らない）
```

⚠️ 試し流しで「配列に素の文字列を足す」（`r := r || 'x=ACCEPTED'`）と 22P02（malformed array literal）になる。
受付の行だけがこの形だったので、受付が「22P02」に見えた。`r := r || ('x=' || ...)` のように式にすること。
