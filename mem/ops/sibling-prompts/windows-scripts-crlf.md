# Windows スクリプト（.bat / .ps1）の「行が消える」問題を点検・修正してください

ジムボード（このアプリの元）で 2026-08-22 に実害が出た問題です。`build-android.bat` の
**約1/4の行が一度も実行されておらず**、`npm run build` が飛ばされて「古い中身のまま
AAB ができる」状態でした。ビルドは最後まで通るので、成果物を見るまで誰も気づけません。

## 仕組み（なぜ行が消えるか）

- `.bat` は UTF-8（日本語コメント入り）で保存されているが、**cmd.exe は CP932 として読む**
- 日本語行の**行末バイト**が `0x81-0x9F` / `0xE0-0xFC`（CP932 の2バイト文字の1バイト目）に
  化けると、cmd は**次の1バイトを無条件に2バイト目として飲む**
- 行末が **LF**（1バイト）だと、飲まれるのは改行そのもの → 行が消え、次の行が前の
  `REM` / `echo` に飲み込まれて実行されない。**CRLF なら CR が飲まれて LF が残る**ので無事
- `.ps1` も同じ。**Windows PowerShell 5.1**（`powershell.exe`＝Windows の既定）は
  **BOM の無い**ファイルを ANSI（=CP932）として読む。根治は **UTF-8 BOM を付けること**
  （PowerShell 7+ は BOM 無しでも UTF-8 なので、BOM があれば両方で正しい）

## やること

1. リポジトリ内の `*.bat` / `*.cmd` / `*.ps1` を全部列挙し、それぞれ
   **改行（CRLF か LF か）と日本語の有無**を調べる
2. 「LF ＋ 日本語コメントあり」のファイルは**壊れている可能性が高い**。
   cmd の読み方をバイト単位で再現して（0x81-0x9F / 0xE0-0xFC の次の1バイトを飲む）、
   実行されるべきコマンド行が行頭に立っているかを確認する。
   ジムボードでは 71行 → 54行 に潰れ、`git checkout --`（pull 前の掃除）・
   `npm install`（optional peer）・`npm run build`・`findstr`（版数表示）が消えていた
3. 修正:
   - `.bat` → **CRLF** に変換
   - `.ps1` → **UTF-8 BOM を付与** ＋ CRLF に変換
   - `.gitattributes` に `*.bat -text` と `*.ps1 -text` を追加
     （`text eol=crlf` ではなく `-text`。リポジトリの中身も CRLF に固定して
     「ファイルを見れば分かる」状態にするため）
   - `.bat` の先頭に**英語で**警告コメントを足す（日本語で書くとこの問題自体で読めなくなる）
4. **見張りテストを追加**する（.bat は CI で実行されないので、形で見張るしかない）:
   - CRLF であること（CR を伴わない LF が1つでもあれば赤）
   - `.ps1` は UTF-8 BOM があること
   - `.gitattributes` の指定が消えていないこと
   - **cmd の読み方をバイト単位で再現**して、主要コマンド（git pull / npm install /
     npm run build / cap sync など、そのスクリプトの本体全部）が行頭に立つこと
5. 変異検証: LF に戻す／BOM を外す／`.gitattributes` の指定を消す／本体コマンドの行を
   消す——それぞれでテストが赤になることを確認してから復旧する。
   ⚠️ 変異の復旧に `git checkout -- <file>` / `git restore` を使わない
   （未コミットの修正ごと消える。cp でバックアップして戻すこと）

## 完了条件

- 全 .bat/.ps1 が CRLF（.ps1 は BOM 付き）で、`.gitattributes` に固定があり、
  見張りテストが緑
- 変異で赤になることを確認済み
- CI（tsc / test / build）グリーン → PR → マージ
