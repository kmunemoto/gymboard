# 自宅向けの動画ライブラリを実装してください

ジムボード（このアプリの元）で 2026-08-31 に実装・本番稼働済みの機能です。
決定事項は変えず、テーブル名・文言はこのアプリの現物に合わせて読み替えてください。

## 🔴 動画ファイルは受け取らない（URL方式）

行が持つのは **YouTube / Vimeo の「限定公開」URL を1つだけ**。アップロードもストレージも
作らない。**これは意識的な決定で、安易に覆さないこと。** 理由:

1. **尺が2桁違う。** チャット添付の上限（このアプリにもあるはず）は「フォーム確認の短い動画」
   向けの数十MB。3分の解説動画は数百MB級
2. **直接受けると付いてくるものが多い。** 変換・サムネ生成・進捗表示・再開可能アップロード、
   そして**署名URLの再発行**。チャットの署名URLは TTL 1時間で、短命な画面だから露呈して
   いないだけ。動画のように長く留まる画面では**確実に切れる**
3. **原価を吸収する場所が無い。** SaaS の値付けが席数だけなら、ストレージと転送量は
   **視聴回数に比例して**増える。動画は「機能を足す」ではなく**原価構造を変える**変更になる
4. 既存のプラン上限トリガーは**行数しか見ない**。流用しても「本数」は縛れるが
   「バイト数」は縛れない

将来ファイルも受けたくなったら `storage_path` 列を足して「URL が NULL なら自前」と
分ければよい。**そのときは 3 を先に決めること。**

## 🔴 貼られたURLをそのまま iframe に入れない

URL は自由入力なので、`javascript:` を入れられるとそのまま実行される。三重で防ぐ:

- **DB**: `CHECK (url LIKE 'https://%' AND char_length(url) <= 500)`
- **クライアント**: 解析関数が**動画IDだけを抜き出して埋め込みURLを組み立て直す**。
  IDに許すのは `[A-Za-z0-9_-]` だけ。元URLのクエリ（`t=` / `feature=` 等）は
  **1つも引き継がない**
- **ホスト判定は末尾一致**（`evil-youtube.com` / `youtube.com.evil.jp` を弾く）
- 解析できなかったものは**画面に出さない**（お客様側は一覧から除外、店側は「URLを開けません」の
  印を出して直してもらう）

見張りテストで「iframe の `src` が、組み立て直した埋め込みURL以外になっていないこと」まで固定する。

## 公開範囲・入口

- **そのお店のお客様全員に共通**。お客様ごとの割り当ては持たない
- 公開制御は `published_at` **1本だけ**（お知らせと同じ）。未来なら見えない＝予約公開。
  下書き・公開トグル・掲載終了は持たない
- お客様側の入口は**ホーム画面のカードだけ**。ナビに出ないタブとして開く

  🔴 **下部ナビに足さないこと。** お客様側にはお店ごとの表示ON/OFFの仕組みが無いことが多く、
  ナビに足すと**全店に出る**。代わりに**公開中の動画が0本ならカード自体を出さない**ことで、
  新しいフラグを増やさずに実質の出し分けにする。
  下部ナビには幾何の不変条件（左右グループの flex 係数 == スロット数）があることが多く、
  触らないほうが安い

- 店側は管理タブ。既存の「タブの表示ON/OFF」の仕組みに乗せる（既定 true、
  簡易プリセットでは出さない、など既存のお知らせ機能と同じ扱いに揃える）
- カテゴリーは自由入力でよい（マスタ化しない）。画面に候補を並べるだけ

## 実装のコツ

- 店側の管理画面で、**URLを貼った直後にその場で試聴できる**ようにする。
  貼り間違い・限定公開になっていない・埋め込み禁止設定、はどれも再生してみないと分からない
- 尺（分:秒）は表示用の任意項目。入力補助を用意する

## 検証

- **本番は3段構え**（読み取り → 適用 → **ロールを演じて**実際に読む）。
  書き込みは全部 `BEGIN … ROLLBACK`
- ロールごとに見える本数を数える。**陽性の対照を必ず置く**:

  | 誰として読んだか | 期待 |
  |---|---|
  | 自店のスタッフ | 公開済み＋予約公開の全部 |
  | 同じ店のお客様 | 公開済みだけ（予約公開は見えない） |
  | **別の店**のスタッフ | **0** |
  | 未ログイン | **0** |

- 書き込みの否定は**トランザクションの中で行数を数える**。ROLLBACK 後に数えると
  「弾かれた」と「巻き戻った」が区別できない。
  お客様の INSERT が RLS 違反で拒否／別店の行の UPDATE が **0行**／
  `javascript:` の URL が CHECK 違反、を確認し、
  **対照として自店スタッフの UPDATE が 1行**通ることも同時に見る

## まだやっていないこと（移植先でも保留でよい）

- **視聴記録**（誰が何を見たか）。「この人はまだ見ていない」を確認したい運用が出たら足す
- **新着のプッシュ通知**。🔴 通知設定に**オプトアウトが無い**場合、毎週上げると
  アクティブなお客様全員に毎回無条件で届く。**通知を足すなら先に切る手段を作ること**
- **実機での再生確認**。`playsinline=1` でインライン再生になるはずだが、
  ネイティブに載せる前に iOS / Android の実機で必ず1度再生すること
