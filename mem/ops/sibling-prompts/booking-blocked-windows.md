兄弟アプリ（セッコツボード・ストレッチボード・ピラボード・ゴルフボード）へ独立実装
させるためのプロンプト。**下の水平線から先を、そのアプリのセッションに丸ごと貼る。**

- 2026-08-03 に上流 merge の運用は終了しているので、コードは運ばずプロンプトで運ぶ
- 各アプリはフォーク後に分岐している。**ファイル名・ヘルパー・SQLSTATE の空きは
  向こうの現物に合わせて読み替えさせる**書き方にしてある
- ジムボードの「予約回数の制限」（booking_frequency_limits・免除）はフォーク後の

# 「受付しない時間帯」を実装してください

予約の**開始時刻を店が決めた2つの時刻に揃え、その間に始まる予約を受け付けない**
機能です。ジムボード（このアプリの元）で 2026-08-21 に実装・本番稼働済みの仕様を
このアプリにも独立実装します。仕様の決定事項は変えないでください。
ファイル名・関数名・文言はこのアプリの現物に合わせて読み替えてください。

## なぜ必要か

このアプリの予約は「セッション時間＋間隔」で1件が帯を占有します（例: 60分＋15分
＝75分。**実際の値はこのアプリの tenants の設定を確認**）。夜のピーク帯に誰かが
中途半端な時刻（例: 19:00）に取ると、その1件が「前は早すぎる」「後は遅すぎる」の
間を独占し、夜が実質1枠に潰れます。開始時刻を2つに揃えれば（例: 18:15 と 19:30、
60分＋15分なら隙間ゼロで連結）、夜が必ず2枠になります。

## 仕様（決定済み・変えないこと）

1. **専用テーブル**を作る（例: `booking_blocked_windows`）。
   `tenant_id / weekdays INTEGER[]（0=日〜6=土）/ start_time / end_time / enabled /
   created_at / updated_at`。既定は帯0件＝**どの店の挙動も変わらない**。
   🔴 **既存の設定テーブルに相乗りしない**。公開済みの旧クライアントが読んで
   誤動作しない（＝旧アプリは表を読まないので画面は従来どおり、DB だけが塞ぐ）
   ことがこの分離の目的。
2. 🔴 **帯は開区間 (start, end)** — `start` / `end` **ちょうどに始まる予約は
   受け付ける**。両端こそが「残したい2枠」そのもの。SQL は `v_min > start AND
   v_min < end`、クライアントも同じ。閉区間にすると店が残したい枠自体を塞ぐ。
3. 🔴 **お客様の自己予約だけに効く**。BEFORE INSERT OR UPDATE トリガーの冒頭で
   `auth.uid() IS NULL OR auth.uid() IS DISTINCT FROM NEW.user_id` なら素通し
   （店側の代理予約とサービスロールは店の裁量）。体験・ゲスト予約にも付けない。
4. **UPDATE の抜け道封じ**: 日時が変わらない UPDATE は見ない。ただし
   「キャンセル済み → 復活」だけは日時不変でも判定する（キャンセル行を帯の中に
   置いて復活させるバイパス）。※status の文言はこのアプリの実値に合わせる。
5. 曜日・分は **JST** で計算（`booking_date AT TIME ZONE 'Asia/Tokyo'`）。
6. **専用の SQLSTATE** で拒否する。🔴 このアプリの migrations を grep して
   `GB0xx` の**未使用の番号**を選ぶこと（ジムボードは GB006 だが、このアプリの
   採番は独立）。クライアントの検出は必ず `error.code`。メッセージ文言で判定しない。
7. トリガー関数は SECURITY DEFINER + `SET search_path = public`、
   `REVOKE ALL ... FROM PUBLIC, anon, authenticated`。
8. **RLS**: RESTRICTIVE のテナント境界／SELECT はテナントの会員全員（会員画面が
   帯の枠を塞いで表示するため）／INSERT・UPDATE・DELETE は owner/trainer のみ／
   anon は REVOKE。CHECK は時刻形式（開始に 24:00 不可・終了のみ 24:00 可）、
   `end_time > start_time`、`cardinality(weekdays) >= 1 AND weekdays <@
   ARRAY[0,1,2,3,4,5,6]`（⚠️ `array_length('{}',1)` は NULL で CHECK を素通りする。
   必ず cardinality）。
9. **テナント削除関数**（delete_my_gym 相当）があるなら、**最新の定義**を全文
   コピーして新テーブルの DELETE を1行足す。🔴 ジムボードで「古い版から写して
   別テーブルの DELETE を落とす」事故を実際に踏んだ。移植後、関数定義から
   `DELETE FROM public.(\w+)` を全部抽出してリポジトリの定義と突き合わせること。
10. **設定画面**: 曜日チップ×開始/終了の Select×有効スイッチ×行削除。
    🔴 時刻は **15分刻み**（30分刻みだと 18:15/19:30 が設定できない）。
    行ごとに「{start} と {end} ちょうどに始まる予約は受け付けます（その間だけを
    受け付けません）」のヒントを出す（誤解が最も起きる場所）。
    保存は**挿入 → 残す id 以外を差分削除**の順（逆だと削除成功→挿入失敗で帯が
    全部静かに消える）。読み込み失敗は「0件」と区別して保存ボタンを塞ぐ。
11. **会員の予約画面**: 帯に当たる枠は、🔴 **普通に埋まった枠の「満枠」表示と
    完全に同一**にする（ラベル・色・全部）。専用の「受付外」文言を**作らない**——
    店が意図的に閉めていることがお客様に見えると仕組みの意味が薄れる
    （ジムボードも当初「受付外」で作り、2026-08-23 に店の要望で満枠へ偽装し直した。
    最初から満枠で作ること）。DB エラーの振り分け（単発・定期・変更）も新コードを
    検出したうえで**満枠の体裁の文言**で案内し、DB の RAISE メッセージも満枠の
    体裁にする（旧クライアントへ素通しで届くため）。定期予約のスキップ案内も
    帯専用の文言を作らず「その他のスキップ」に合流させる。
    **店側（設定画面・代理予約エラー）だけは「受付しない設定」と正直に出す。**
    空き待ち（waitlist があれば）の対象からも外す（待っても取れない）。
    判定は「枠の生成・送信直前・予約変更の直前」の3箇所。
12. **読み取りフック**は「読めなければ空配列＝帯なし」に倒す（未適用環境や権限
    問題で**予約が取れなくなるより従来どおり取れるほうが安全**。最終判定は DB）。
13. **免除機構がこのアプリにある場合のみ**（ジムボードの booking_frequency_limits
    の exempt 相当。無ければこの項は丸ごと省略）: 免除は帯より強い。トリガーで
    帯の判定より**前**に免除の EXISTS を置き、当たれば素通し。クライアントも同順。
14. i18n はこのアプリが持つ**全言語**にキーを揃える（fallback で日本語が出ないか
    検査）。文言の「ジム」相当語はこのアプリの業種語彙に合わせる。

## 検証（この規律で。省略しない）

- テストは SQL を migrations から読んで**最後の定義**に対して検査する形
  （CREATE OR REPLACE は最後しか残らない。連結全体へのマッチは骨抜き上書きを
  見逃す）。行末コメントを落としてから検査。
- **変異検証**を最低これだけ: 開区間→閉区間（クライアント/SQL×両端）／自己予約の
  絞りを削除／SQLSTATE を既存コードに取り違え／テナント削除関数の新行を削除／
  15分刻み→30分刻み／お客様向け文言を「受け付けていません」系に差し替え
  （⚠️ 文言の見張りは**否定＋肯定の両建て**で。「受付」の grep だけだと
  送り仮名入りの「受け付け」をすり抜ける——ジムボードの変異検証で実際にすり抜けた）。
  **全部赤→復旧緑**を確認してから先へ進む。
- ゲートは CI と同じコマンド・`npm test` は**終了コード**で判定
  （テスト全緑でも Errors N errors で exit 1 のことがある）。
- 本番適用は 3段構え: 読み取りで現状 → 適用 → **お客様/オーナー/anon を演じた
  実書き込み**（すべて BEGIN...ROLLBACK）。最低この15ケース:
  帯の始端ちょうど=通る／帯の中3点=拒否／終端ちょうど=通る／対象外の曜日=通る／
  代理予約=通る／（免除があれば）免除の会員=通る／帯の外→中への UPDATE=拒否／
  enabled=false=効かない／会員は帯を読める・作成/無効化/削除は不可／anon は読めない。
  ⚠️ 検証用の空き枠はセッション占有時間ぶん重なる。「夜が完全に空いている平日」を
  先に探すこと。
- ⚠️ Lovable の `query_database` が 499 `request_cancelled` を返したときは、
  **適用されていないことも、遅れて適用されることもある**。再実行の前に必ず実際の
  オブジェクトの状態を確認し、確認が「無い」でも少し置いてもう一度見る
  （ジムボードで「確認時は無い→再実行したら一意制約違反」を実際に踏んだ）。

## 既知の制約（そのまま記録に残す）

帯は**開始時刻しか見ない**。帯の始端より前の開始（例: 18:00 開始が 19:15 まで
占有）が入ると、始端の枠（18:15）は満枠で取れないことがある。必要になった店には
営業時間の開始を寄せるか帯を広げる運用で対応する。
