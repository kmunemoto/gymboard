# 表示量プリセット（機能が多すぎる問題への対処）

## 背景

ジムボードは機能を足し続けた結果、新しいジムが**いきなり17項目すべて表示された状態**で
始まるようになっていた。パーソナルジムを1人で回しているオーナーにとって、初日から
「稼働率ヒートマップ」「カウンセリング」「体験フォロー」まで並んでいるのは多すぎる。

個別のトグル（`mem/features/gym-display-visibility.md`）は既にあるが、
17項目を1つずつ判断させるのは現実的でない。

## 入れたもの

**表示量プリセット 3段階**（`src/lib/gymDisplaySettings.ts`）:

| プリセット | 表示するもの |
|---|---|
| シンプル | 本日のセッション / アクティブ顧客 / 本日のスケジュール / 種目管理 |
| 標準 | ＋ 月間セッション・今月売上・売上推移・フォローが必要な顧客・更新が近い顧客・メッセージ・お知らせ |
| フル | 全17項目（＝DBの既定値、従来どおり） |

包含関係（シンプル ⊂ 標準 ⊂ フル）はテストで担保している。

適用箇所は2つだけ:

1. **オンボーディング**（`src/pages/Onboarding.tsx` ステップ1）: 新規ジムが選ぶ。**既定は「標準」**
2. **ジム設定 → 表示・デザイン**: 3つのボタンでいつでも一括切替。個別トグルはその下にそのまま残る

### 既存ジムの表示は変わらない

DBの既定値は今までどおり全て `true`。プリセットが効くのは上記2つの場面だけで、
既存ジムが勝手にシンプルになることはない。設定画面では、今の設定に一致するプリセットが
選択状態になり、どれとも一致しなければ「個別に調整済み」と表示する（`detectPreset`）。

## 併せて直した既存バグ: useTenant がコンポーネントごとに独立していた

`npm run dev:fixtures` で実機確認したところ、**設定画面でプリセットを押しても
サイドバーのタブが消えなかった**。

原因は `useTenant()` が呼び出しごとに独立した `useState` を持っていたこと（26ファイルが利用）。
設定画面の `refetch()` はそのコンポーネントの state しか更新しないため、同時にマウント
されている `TrainerSidebar` は古いテナント情報を持ち続けていた。
ダッシュボードは「タブを切り替えると再マウントされる」ため偶然反映されて見えており、
サイドバーだけが常駐しているので露見した。

これはプリセットに限らず、**メニューのタブをOFFにしてもメニューから消えない**という
既存機能の不具合でもあった（PR #185 の時点から）。

修正: `muscleGroup.ts` / `tenantMuscleGroups.ts` と同じ「モジュール単位のキャッシュ＋購読」
パターンに変更し、全ての利用箇所が同じ状態を共有するようにした。
`useTenant()` の戻り値の形は変えていないため、26ファイルの呼び出し側は無改修。

副次的な効果として、1画面で同じ tenant クエリが利用箇所ぶん飛んでいた無駄も無くなった
（`src/test/useTenantShared.test.tsx` が「同時マウントでも取得は1回」を検証している）。
