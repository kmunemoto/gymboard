# 受付しない時間帯（booking_blocked_windows・GB006）（2026-08-21）

「平日は **18:15 の回と 19:30 の回だけを残し、その間に始まる予約を受け付けない**」
のように、開始時刻を揃えて枠数を確保するための帯。

## なぜ必要か（Salute御所南で実際に起きた）

予約は 60分セッション＋間隔15分＝1件が75分を占有する。誰かが 19:00 に取ると
19:00–20:15 が埋まり、**前の枠は 17:45 開始が最後（早すぎる）・次は 20:15 開始
（遅すぎる）**で、その1件が夜を実質1枠に潰す。開始時刻を 18:15 と 19:30 に
揃えれば、18:15 の回の解放（19:15＋15分）ちょうどに 19:30 の回が始まり、
**隙間ゼロで夜が必ず2枠**になる。

回数の制限（GB003）では表現できない（「回数」ではなく「開始時刻の位置」の問題。
max_bookings=0 は CHECK で意図的に禁止している）。

## 🔴 帯は**開区間 (start, end)** —— 両端ちょうどの開始は受け付ける

両端こそが「残したい2枠」そのもの。18:15〜19:30 の帯は 18:30〜19:15 開始を塞ぎ、
18:15 開始と 19:30 開始は取れる。閉区間にすると店は残したい枠自体を塞ぐ。

**時間帯の区間規則は3機能で意味により使い分けている**（テストが3つとも固定）:

| 機能 | 区間 | 意味 |
|---|---|---|
| 容量の帯（booking_capacity_windows） | [start, end) 半開 | スタッフが居る期間 |
| 回数の制限（booking_frequency_limits） | [start, end] 閉 | 制限する開始時刻の範囲（店の「〜19:00」=19:00の回まで） |
| **受付しない帯（この表）** | **(start, end) 開** | **残す2枠の「間」** |

設定 UI の時刻は **15分刻み**（他の帯は30分刻み。ここだけ 18:15/19:30 のような
実際の枠に合わせる必要がある）。行ごとに「{start} と {end} ちょうどに始まる予約は
受け付けます」のヒントを出す（誤解がいちばん起きる場所）。

## 🔴 効くのは自己予約だけ・免除は帯より強い

- トリガー（guard_booking_blocked_window）は auth.uid() = NEW.user_id だけを見る。
  **店側の代理予約は帯の中でも入れられる**（GB003/GB004 と同じ非対称。店の裁量）
- **免除（booking_frequency_limits.exempt、閉区間）に当たるお客様は帯の中でも取れる**
  （「免除は制限より強い」の原則をここにも通した）
- 体験・ドロップイン（trial_bookings）には付けない（GB003 と同じ判断。ゲストに
  会員概念が無い。帯の中に体験が入る事故が実害になったら trial 側の付与を検討）
- 'キャンセル済み' からの復活は日時不変でも判定（バイパス封じ。GB003 と同じ）

## 🔴 旧アプリとの互換のため回数制限の表に相乗りしない

「0回まで」として booking_frequency_limits に載せる案は、**公開済みクライアント
（閉区間で判定）が残したい両端の枠までグレーにする**。別の表なら旧アプリは
読まない＝画面は従来どおりで、DB のトリガーだけが塞ぐ（押すと GB006 エラー）。
新アプリは帯の枠を表示で塞ぎ、空き待ちの対象からも外す（待っても取れない）。
~~表示は「受付外」~~ → **2026-08-23 から「満枠」に偽装**（下の節）。

## 🔴 お客様には「満枠」として見せる（2026-08-23 の決定）

当初は帯の枠に「受付外」の専用ラベルを出していたが、宗本さんの要望で
**普通に埋まっている枠と完全に同じ「満枠」表示**へ変えた。専用文言を出すと
「店が意図的にこの時間を閉めている」ことがお客様に見えてしまい、
この仕組みの意味が薄れるため。**帯の存在はお客様向けのどの文言にも出さない**:

- グリッド: **表示層で帯を「埋まっている枠」と同一視する**。
  `const displayBlocked = slot.blocked || slot.notAccepting;` を1本置き、
  ラベル・空き待ちの可否・`viewOnlyOpen` の3箇所すべてがこれを見る。
  🔴 **`slot.notAccepting` を名指しで分岐させない**（この定義1箇所だけ。見張りテストが
  出現回数を1に固定している）
- エラートースト（単発・定期・リスケの GB006 分岐）: `errorNotAccepting` を
  「この枠は満枠のためご予約いただけません…」の体裁に（5言語とも）
- 定期予約のスキップ案内: 帯スキップ専用トースト（repeatSkippedBlocked）は削除し、
  その他スキップ（otherSkipped）に合流
- DB の GB006 RAISE メッセージも満枠の体裁（20260823010000）。届くのは
  帯機能より前の旧クライアントだけだが、そこから漏れるのを塞ぐ
- **空き待ちも満枠と同じく登録できる**（2026-08-23 に方針変更。下の「ラベルだけ
  揃えても足りなかった」参照）。空き通知は**実際の予約のキャンセル**でしか発火しない
  ので、帯の枠に待機者が付いても「誰もキャンセルしない満枠」として静かに待つだけ。
  ⚠️ 帯の中に実予約がある枠（`blocked && notAccepting`）でその予約が消えると、
  待機者に「空きました」が飛ぶのに取れない（GB006）。文言は満枠なので
  「先に取られた」と読める範囲だが、頻度が上がるようなら通知側で帯を除く
- **店側は明示のまま**: 設定画面・代理予約の `errorNotAcceptingProxy` は
  「受付しない設定」と正直に出す（お客様には出ない文言）
- 消したキー: `slotNotAccepting` / `repeatSkippedBlocked`（復活の見張りテストあり）

### 🔴 ラベルだけ揃えても足りなかった（2026-08-23・同日に追加修正）

最初の実装は**ラベルだけ**「満枠」に揃えたが、30体のエージェントで漏れ経路を総ざらい

| | 本物の満枠 | 帯の枠（修正前） |
|---|---|---|
| ボタン | 押せる → キャンセル待ちダイアログ | `disabled`・タップ無反応 |
| 文字 | `text-muted-foreground/60` ＋ hover | `/40`・`cursor-not-allowed` |
| 締切後(tooSoon)の日 | 灰色の満枠 | **`viewOnlyOpen` でアクセント色＝空き枠の見た目** |

### 残る限界（直していない・お客様には見えうる）

1. 🔴 **公開ページ（体験・ドロップイン）は帯を見ない**。会員アプリが「満枠」と出す
   時刻が `/trial` では予約可に見える。帯は体験に効かせない決定（GB003 と同じ）が
   前提なので、直すなら**体験にも帯を効かせるか判断が要る**（店の裁量・要相談）
2. **帯の設定表は会員なら REST で読める**（`booking_blocked_windows` の SELECT が
   テナント会員に開いている）。画面には出ないが DevTools で表名と曜日・時刻が見える。
   クライアントが枠を塞ぐのに帯を必要とする構造なので、塞ぐには
   「埋まっている枠」に合成して返す RPC 化が要る（未着手）
3. **満枠の「広がり方」が物理的にあり得ない**。実予約は 60＋15＝75分を占有するので
   前後も必ず満枠になるが、帯は開始時刻だけを見るため「18:15 空き / 18:30〜19:15 満枠
   / 19:30 空き」という孤島ができる。**直すと残したい 18:15・19:30 まで塞がる**ので
   直せない（この機能の目的そのもの）
4. **公開済みの旧アプリ（iOS 1.5.9 等）は今も「受付外」と表示する**。ロケールは
   ビルドに埋め込まれるので DB からは直せない。**次のネイティブ配布まで方針は未達成**

⚠️ 文言の見張りテストは**否定＋肯定の両建て**で書くこと。最初は「受付系の語を含まない」の
否定だけで書いたが、`/受付/` は送り仮名入りの「受け付けていません」に**マッチしない**ため、
文言を元に戻す変異が緑のまますり抜けた（変異検証で発見）。いまは各言語について
「満枠の語を含む」の肯定チェックも入れてある。

## 食い込み対策: 帯を3本連結して夕方以降を4枠に固定（2026-08-22 適用）

宗本さん自身が穴に気づいた:「17:30 や 20:00 に取られると、占有（75分）が
食い込んで 18:15 / 19:30 の枠が潰れる＝このシステムが無駄になる」。
帯は**開始時刻しか見ない**ので、帯の外ぎりぎりの開始が防御の穴だった。

対策は開発なし・**帯を2本追加**しただけ:

| 帯 | 止まる開始 | 残る両端 |
|---|---|---|
| 平日 17:00〜18:15（追加） | 17:15〜18:00 | 17:00・18:15 |
| 平日 18:15〜19:30（既存） | 18:30〜19:15 | 18:15・19:30 |
| 平日 19:30〜20:45（追加） | 19:45〜20:30 | 19:30・20:45 |

これで平日の夕方以降は **17:00 → 18:15 → 19:30 → 20:45** の4本だけになり、
75分ぴったりの間隔で**隙間ゼロの連結**＝どれを取られても他は潰れない。
16:45 開始は占有が 18:00 で終わるので許容（帯の外で正しい）。

- 🔴 **1本の長い帯（17:00〜20:45）にまとめてはいけない**。両端しか残らないので
  中の 18:15・19:30 まで塞がる。「残したい枠の間」ごとに1本ずつ
- 適用直後に城後さんを演じて12時刻を総当たり（すべて ROLLBACK・成功は即削除で干渉排除）:

  ```
  16:45 ○ / 17:00 ○ / 17:15 × / 17:30 × / 18:00 × / 18:15 ○ /
  18:30 × / 19:30 ○ / 19:45 × / 20:00 × / 20:30 × / 20:45 ○（×はすべて GB006）
  ```

- ⚠️ この連結は**セッション60分＋間隔15分＝75分**が前提。90分プランのような
  長い占有を導入すると食い込み幅が変わるので、帯の幅も見直すこと
