# Googleカレンダー連携の「確認されていません」を消す（OAuth 審査）

2026-09-19、お客様から店のチャットに届いた:

> （スクリーンショット）このアプリは Google で確認されていません

宗本さんの判断: **審査を通す。**

---

## 何が起きているか

お客様の設定にある「Googleカレンダー連携」は Google OAuth を使い、
**`https://www.googleapis.com/auth/calendar.events`** を要求している。
これは Google が**機密スコープ**に分類する権限で、**審査を通していないアプリ**が
要求すると、**開発者本人のアカウント以外には必ず警告**が出る。

宗本さんだけ登録できるのは、Google Cloud プロジェクトの持ち主だから。
お客様側の不具合ではない。

⚠️ **Google ログイン（サインイン）は無関係。** あちらが要求するのは
`email` / `profile` / `openid` だけで機密スコープではないため、警告は出ない。
同じ同意画面を共有しているので、**審査の作業でログインを壊さないこと。**

## 🔴 承認済みドメインの件（提出時は止め金にならなかったが、指摘されうる）

**いまのリダイレクトURIは Supabase のドメインになっている:**

```
https://<Supabaseのref>.supabase.co/functions/v1/google-calendar-callback
```

Google の審査は「**申請者が所有し、Search Console で所有権を確認したドメイン**」を
前提に進む（ホームページ・プライバシーポリシー・利用規約のURL、および
承認済みドメインの一覧）。**`supabase.co` は宗本さんの所有ドメインではない**ため、
ここが引っかかる可能性が高い。

### 確かめかた

Google Cloud Console → **OAuth 同意画面** →「承認済みドメイン」を開く。

- `kyoto-salute.com` を追加できて、**保存できるか**
- OAuth クライアントの「承認済みのリダイレクト URI」に `*.supabase.co` が残ったまま
  審査に出せるか（警告や赤字が出ないか）

引っかかる場合の直しかたは2つ:

1. **リダイレクトURIを自前ドメインに移す**（推奨）
   `https://app.kyoto-salute.com/...` にコールバック用の画面を作り、受け取った
   `code` を既存の `google-calendar-callback` に渡す。**コード側の作業なので
   こちらでやれる。** ネイティブアプリからの戻り（ディープリンク）も一緒に直す必要がある。
2. Supabase のカスタムドメイン機能を使う
   → ジムボードの Supabase は **Lovable Cloud の持ち物**なので、
     こちらから設定できない。基本は 1 を選ぶ。

🔴 **これを確かめる前に、デモ動画や申請文を作り込まないこと。**

## Console での手順（宗本さんの作業）

1. **Search Console でドメインの所有権を確認**（`kyoto-salute.com`）
   OAuth 同意画面と**同じ Google アカウント**で行うこと。別アカウントだと反映されない。
2. **OAuth 同意画面**を埋める
   - アプリ名・ロゴ・サポートメール
   - 承認済みドメイン: `kyoto-salute.com`
   - プライバシーポリシー / 利用規約のURL（上記）
3. **スコープ**に `.../auth/calendar.events` を登録し、**なぜ必要かを1〜2文で書く**
   例:「ジムの予約が入ったとき、利用者本人のカレンダーに予定を作成・更新・削除するため。
   それ以外の目的では使用しない」
4. **デモ動画**（YouTube・限定公開可）を撮る。下記の通りに映す
5. **審査に提出**。追加質問がメールで来るので必ず返す（放置すると却下される）

### デモ動画に映すもの

審査担当は「その権限が本当に要るか」だけを見る。映すのはこの順:

```
1. ブラウザのURL欄に app.kyoto-salute.com が見えている状態から開始
2. アプリにログイン
3. 設定 →「Googleカレンダー連携」→ 連携する を押す
4. Google の同意画面で、要求しているスコープが見えている
5. 許可したあと、予約を1件入れる
6. Googleカレンダーにその予定が入ったところを見せる
7. 予約をキャンセルして、予定が消えるところまで見せる
```

⚠️ 音声は不要。**URL 欄を隠さないこと**（同一ドメインであることの証拠になる）。

## 審査が通るまでの案内（お客様向け）

**「Googleカレンダー連携」は使わず、予約完了画面の「Googleカレンダーに追加」を
押してもらう。** こちらは権限も連携も不要で、警告は一切出ない。

| 経路 | 権限 | 警告 | 自動で入るか |
|---|---|---|---|
| 予約完了画面の「Googleカレンダーに追加」 | 不要 | 出ない | 予約ごとに1タップ |
| 設定 →「Appleカレンダー連携」（ICS購読） | 不要 | 出ない | 自動。ただし Google で使うにはPCでURL登録が要る |
| 設定 →「Googleカレンダー連携」 | 機密スコープ | **出る** | 自動 |

実装:
- 予約完了 … `src/components/customer/BookingCompleteDialog.tsx`（`action=TEMPLATE` のリンク）
- ICS購読 … `supabase/functions/calendar-feed` ＋ `CustomerSettings.tsx`
  （`profiles.calendar_token`。本番は全76人が発行済み）

## 通らなかった / やめる場合

`src/lib/featureFlags.ts` の

```ts
export const GOOGLE_CALENDAR_CUSTOMER_ENABLED = true; // お客様設定の連携セクション
```

を `false` にすれば、お客様の設定から連携セクションごと消える。
**トレーナー側（`GOOGLE_CALENDAR_TRAINER_ENABLED`）は別のフラグ**なので、
店側の同期は残せる（人数が少なく、警告を越えて進める運用でも回る）。

⚠️ このフラグは**全テナント共通**。1店だけ消すことはできない。
