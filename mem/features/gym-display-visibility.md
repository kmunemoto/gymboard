# ジム側（トレーナー画面）の表示ON/OFF

## 概要（2026-07〜）
トレーナー画面の表示要素を、ジムごとに個別にON/OFFできる。使わない機能を隠して
ホーム画面・メニューをジムの運用に合わせて絞り込める。

設定場所: `TrainerGymSettings.tsx`「表示設定」セクション（3グループ）。

| グループ | 対象 | カラム |
|---|---|---|
| 統計カード | 本日のセッション / アクティブ顧客 / 月間セッション / 今月売上 | `show_stat_*`（4） |
| ホーム画面のセクション | 本日のセッション・体験フォロー待ち・フォローが必要な顧客・更新が近い顧客・カウンセリング回答・売上推移・稼働率ヒートマップ | `show_today_schedule` ほか（7） |
| メニュー | メッセージ・種目・カウンセリング・お知らせ・通知・体験フォロー | `show_nav_*`（6） |

## 設計
- **定義は `src/lib/gymDisplaySettings.ts` に集約**。設定画面のトグル一覧と、実際に
  出し分ける側（`TrainerSidebar` / `TrainerDashboard` / `TrainerView`）が同じ定義を参照する。
  別々に持つと「設定にはあるが効かない」「隠したのに設定に出てこない」というズレが出るため。
- 判定は全て `!== false`（`isDisplayOn`）。**列が無い/未取得でも既定は表示**なので、
  マイグレーション未適用の環境でも従来どおり全部表示される。既存の
  `show_retention_alerts` / `show_stat_*` と同じ方針。
- 更新は1つの汎用ハンドラ `handleToggleDisplay(column, checked)` に統一（17項目ぶんの
  ほぼ同型の処理を書かない）。保存中フラグは「どのカラムを保存中か」で共有する。
- `show_retention_alerts` は既存カラムをそのまま「ホーム画面のセクション」グループに
  取り込んだ（新カラムを作らず互換維持）。専用の
  `settings.trainer.showRetentionTitle/Desc` キーは未使用になったが、5言語ぶんの削除は
  churn が大きいため残置。

## 隠せないもの（意図的な制限）
**ホーム・顧客・予約・設定タブは対象外**。隠すとジム自身が操作不能になり得るため
（特に設定を隠すと、この設定画面自体に戻れず元に戻せなくなる）。
`gymDisplaySettings.test.ts` でこの不変条件をテストしている。

## 落とし穴
- **今開いているタブはメニューから消さない**（`TrainerSidebar` の `isVisible` が
  `tabId === activeTab` を例外にしている）。消すと、そのタブを見ている最中に
  自分の居場所がメニューから消えて操作の文脈を見失うため。
- **メニューを隠しても機能自体は生きている**。他画面からの遷移（離脱アラートの
  「声かけ」→メッセージ画面 等）はそのまま動く。ここを塞ぐと既存導線が壊れるため、
  あくまで「メニューから消す」だけに留めている。
- メッセージをメニューから隠したジムでは、`TrainerView` ヘッダーのチャットボタンも
  併せて隠す（メニューに無いのにヘッダーからだけ入れる、というちぐはぐを防ぐ）。
- 各セクションが元々持っていた表示条件（該当データが0件なら出さない等）はそのまま。
  トグルは「出す/出さない」の上位スイッチとして AND で効く。

## デプロイに関する注意
`supabase/migrations/20260723100000_add_gym_display_visibility.sql` はLovable経由での
適用が必要。`useTenant.ts` の `COL_VARIANTS` に未適用環境向けのフォールバック段を
追加済みのため、適用前でも既定true（全表示、従来どおり）で安全に動作する。
