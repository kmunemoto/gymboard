# くり返しブロック（blocked_slots.recurrence_group）（2026-08-22）

「決まった曜日の決まった時間帯を毎週ブロックしたい。1回ずつ入れるのは面倒」
（宗本さんの要望）への対応。ブロック作成ダイアログに**毎週×N週**のセレクタを足し、
1回の操作で最大12週（約3ヶ月）ぶんの実体行をまとめて作る。

## 🔴 方式は「実体行×N」。恒久ルールの表にはしない

booking_blocked_windows のような weekday×時刻のルール表にしなかった理由:

- ブロックの判定は **blocked_slots の実体行を読む箇所に散っている**
  （クライアントの checkSlotBlocked / get_tenant_booked_slots・ドロップインの RPC）。
  ルール表を足すと、**公開済みの旧クライアントがその帯を「空き」と誤表示して
  予約を通してしまう**（DB にブロックの重なりを拒否するトリガーは無い。
  受付しない帯 GB006 とは違い、ブロックはクライアント判定が主体）
- 実体行なら旧クライアントも今までどおり読む＝**互換性の問題がゼロ**。
  定期予約（createRecurringBookings）と同じ判断

12週で足りない場合は「消化されたらまた入れる」運用（無限のルールが必要になったら、
そのとき初めてルール表＋DBトリガーをセットで設計する）。

## 仕様

- セレクタは 1・2・3・4・6・8・10・12週（ブロックは休憩・貸し出しなど固定予定が
  多いので、定期予約の4回より長い12週まで）
- **予約やブロックと重なる週はスキップ**して作成し、スキップした日付をトーストで知らせる。
  全週スキップなら何も作らずエラー表示
- 繰り返しで作った行には共通の `recurrence_group`（UUID）を積む。
  🔴 **繰り返しのときだけ**積む（未適用のDBに常に積むと PGRST204 で単発ブロックまで
  作れなくなる。staff_user_id と同じ作法）
- 解除ダイアログ: 対象がくり返しブロックのときだけ「まとめて解除」のチェックを出す。
  🔴 消すのは**その日以降**だけ（`gte(blocked_date)`。過去の行は実績として残す）。
  チェック状態はダイアログを開くたびに false へ戻す（3導線すべて）
- 日付の加算は `new Date(y, m-1, d + i*7)` のローカル日付演算（TZずれ無し）
