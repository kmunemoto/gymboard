# 時間帯ブロックを「毎週×N週」でまとめて作成・解除できるようにしてください

店側の時間帯ブロック（休憩・貸切など。blocked_slots 相当のテーブルを確認）を、
1回の操作で「毎週 同じ曜日・同じ時間帯 × 最大12週」まとめて登録できるようにします。
ジムボード（このアプリの元）で 2026-08-22 に実装・本番稼働済みの仕様です。

## 仕様（決定済み・変えないこと）

1. 🔴 **方式は「実体行×N」**。weekday×時刻の恒久ルール表には**しない**。
   ブロックの判定はクライアント（checkSlotBlocked 相当）と空き枠 RPC が
   **実体行を読む**形で散っており、ルール表を足すと**公開済みの旧アプリがその帯を
   「空き」と誤表示して予約を通してしまう**（DB にブロックの重なりを拒否する
   トリガーは無い）。実体行なら旧アプリも今までどおり読む＝互換性の問題ゼロ。
   12週で足りない運用は「消化されたらまた入れる」でよい
2. ブロックのテーブルに `recurrence_group UUID` を追加（＋部分インデックス）。
   🔴 **繰り返しのときだけ**積む——未適用の DB に常に積むと PGRST204 で
   **単発ブロックまで作れなくなる**
3. 作成ダイアログに「毎週×N週」セレクタ（1・2・3・4・6・8・10・12週）。
   **予約や既存ブロックと重なる週はスキップ**して作成し、スキップした日付を
   トーストで知らせる。全週スキップなら何も作らずエラー表示
4. 解除ダイアログ: 対象がくり返しブロックのときだけ「まとめて解除」のチェックを出す。
   🔴 消すのは**その日以降**だけ（`gte(日付)`。過去の行は実績として残す）。
   チェック状態はダイアログを開くたびに false へ戻す（**全導線**で）
5. 日付の加算は `new Date(y, m-1, d + i*7)` のローカル日付演算（TZ ずれ無し）。
   UTC 演算にしない

## 検証

- 変異検証: グループ常時積み／日付フロア無し削除／週スキップ削除／チェックの
  リセット漏れ／UTC 日付演算——で赤を確認（ジムボードは10種で検証した）
- 本番3段構え: 列＋インデックス適用 → 店を演じて4週分の実 INSERT（同一
  recurrence_group）→ お客様は読めるが書けない → 「この日以降」の series DELETE が
  過去行を残して未来行だけ消す——すべて BEGIN…ROLLBACK・残留0件
- migration はマージ直前に本番へ適用（types.ts 再生成レース）
- 5言語・ゲートグリーン → PR → マージ
