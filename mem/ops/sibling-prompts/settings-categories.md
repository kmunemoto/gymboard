# 店側の設定画面をカテゴリー分けして2階層にしてください

店側の設定画面（TrainerGymSettings 相当）が20項目前後の縦一覧になっているはずです。
iOS の設定アプリ式に**「一覧（カテゴリーの行）→ タップで該当ページ」の2階層**へ
整理します。ジムボード（このアプリの元）で 2026-08-23 に実施済み。

## 仕様（決定済み・変えないこと）

1. 🔴 **各セクションの JSX・保存ロジックは一切変えない**。内部状態
   `settingsView: カテゴリー | null` と表示ガード `{view === "x" && …}` だけで
   出し分ける（URL は変えない・ルーターも足さない）。組み替えはセクションの
   マーカーコメント単位の機械的な移動で行い、中身を書き直さない
2. **毎日使う項目はカテゴリーに入れず一覧の最上部に直接置く**（ジムボードは
   招待コード。過去に「開いてすぐ使えること」という店の要望があった——
   このアプリにも相当する「日常使いの1枚」が無いか先に確認する）
3. カテゴリーは業務語彙で7〜10行・グループ見出し2〜4個に収める。ジムボードの分け方
   （ジム/予約/案内・表示/サポート）を出発点に、このアプリの機能構成へ合わせる。
   行はアイコン＋ラベル＋中身の説明（truncate）＋chevron
4. **機能フラグでセクションが丸ごと消えるカテゴリーは行ごと消す**（開き先が
   空のページになる行を残さない）。オーナー限定のセクションだけのカテゴリーは
   行も role で出し分ける
5. 一覧の最下部にログアウト・退会系をそのまま残す（カテゴリーに隠さない）
6. 開閉時に `window.scrollTo({ top: 0 })`。戻るは「← 設定画面のタイトル」の行
7. i18n はこのアプリの全言語にカテゴリー名＋説明のキーを追加

## 検証

- 設定画面をレンダリングして中身を検査している**既存テストが必ず落ちる**。
  「先にカテゴリーの行をクリックする」形に直す（検査の意図は弱めない。
  フラグOFF系は「行ごと消える」ことも見る）。jsdom に window.scrollTo が無いので
  テストの setup でスタブする
- 構造テストを追加: 最上部の直接置きの項目がカテゴリーの行より DOM 上で前／
  一覧→開く→戻るの遷移／一覧の時点では各セクションの中身が出ていない
- ゲートは CI と同じコマンド・`npm test` は終了コードで判定 → PR → マージ
