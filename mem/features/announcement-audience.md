# お知らせの配信対象「全員から除く」「個別（複数）」（2026-10-27）

## 決めたこと（既定の判断）

配信対象を3つにした。

| 画面のボタン | `announcements.target` | 届く人 |
|---|---|---|
| 全員 | `all` | 在籍のお客様全員（今まで通り） |
| 全員から除く | `except` | 全員から、選んだ人を除く |
| 個別 | `only` | 選んだ人だけ（**複数選べる**ようにした。以前は1人だけ） |
| （古いアプリ） | `<user_id>` | その1人。読むのも送るのも今まで通り。新しい画面で編集すると `only` の1人になる |

- 選んだ人は `announcement_audience`（announcement_id, user_id, tenant_id）に1行ずつ。
  **店のスタッフだけ**が読み書きする（お客様に「誰が除かれたか」「ほかに誰に送ったか」を見せない）
- 除いた人には**通知も届かず、お知らせの一覧にも出ない**
- 「全員から除く」と「個別」を切り替えると、選んだ人は空に戻す
  （「除く」で選んだ人が、そのまま「個別」の送り先に化けるのを防ぐ）

## 🔴 出し分けは DB の読み取り権限（RLS）

お客様のお知らせ一覧・未読の数（`useAnnouncements`）は `announcements` を直接読んでいて、画面では絞っていない。
読み取り権限（`Users view own/all announcements`）に except / only の枝を足したので、
**古いアプリのお客様にも**効く。判定は `announcement_audience_has(お知らせ, 人)`（SECURITY DEFINER。
お客様は名簿の表を読めないため）。

## 🔴 保存は `save_announcement`（1つのトランザクション）

お知らせの行と選んだ人を別々に書くと、その間に配信の定期実行（`push-announcements`）が
「除く人がまだ居ない」状態を拾って**全員に送る**ことがありうる。行と選んだ人を同じトランザクションで書く
関数を用意し、画面はそれだけを使う。SECURITY INVOKER なので、書けるかどうかは今までの RLS のまま
（トレーナーだけ・自分のジムだけ・相手はそのジムの在籍者だけ）。

- 新規は `p_id` なし、更新は `p_id` あり。選んだ人は差分だけ書く
- `except` / `only` で誰も選んでいないと `audience_required`（画面でも止める）
- ジムは `get_my_tenant_id()` で決まる（画面から渡さない）

古いアプリのトレーナー画面は今まで通り表へ直接書く（`all` か `<user_id>`）。それはそのまま動く。

## 🔴 プッシュ通知（`push-announcements`）

- `except`: 在籍（active）のお客様全員から、選んだ人を引く
- `only`: 選んだ人
- **選んだ人が読めなかったときは送らない。** クレーム（`push_sent_at`）を外して、次の実行でやり直す
  （除くはずの人に届くよりまし）
- Edge Function は push しても本番に出ない。Lovable にデプロイを頼む（`mem/ops/edge-function-deploy.md`）。
  未デプロイの間に `except` / `only` のお知らせを出すと、古い関数は `target` を user_id として扱い、
  **誰にも送らない**（全員に送る方向には壊れない）
