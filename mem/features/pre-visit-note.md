# 「ご来店前のお願い」（2026-10-27）

## 要望

宗本さん:

> お客様にトレーニング前の１～２時間前にエネルギーになるものを摂取してお越しくださいという意味の
> 文章？注意書き？お願い？を伝えたい。そういうのを設定できる仕組みを考えて、作って

出す場所を3案（アプリ内だけ／アプリ内＋前日の通知／さらに数時間前の専用通知）で聞いて、
**「アプリ内だけ」**に決まった。

## 見せ方

店が書いた文を、見出し「ご来店前のお願い」つきでそのまま出す（`src/components/booking/PreVisitNote.tsx`）。
出す場所は「ご来店は 13:55 以降に」（`mem/features/arrival-guide.md`）と同じ3か所:

| 場所 | 出し方 |
|---|---|
| 会員の予約完了画面（`BookingCompleteDialog`） | 来店の目安時刻のすぐ下 |
| 会員のホーム「次回の予約」（`CustomerHome`） | カードの下（`compact`＝小さめの文字） |
| 体験予約の完了画面（`TrialBooking`。未ログイン） | 来店の目安時刻のすぐ下 |

- 文は**店が自由に書く**（食事に限らない。「タオルをお持ちください」なども入る）。改行もそのまま出す
- **通知・メールには入れていない**（「アプリ内だけ」）。メールに載せたいときは、既にある店ごとの一文欄
  （`booking_email_note` / `reminder_email_note`。設定 → メール・通知）に同じ文を入れれば今日から載る

## 店ごとの設定

`tenants.pre_visit_note`（text・NULL 可。CHECK は 300 文字まで＝`PRE_VISIT_NOTE_MAX`）。
設定 → 予約のルール →「ご来店前のお願い」（`PreVisitNoteCard`。来店の目安時刻のカードの隣）。

- 🔴 **既定は NULL＝何も出さない。** 上流が文言を代弁しない（`cancel_policy_body` と同じ方針）。
  例文は「例文を入れる」ボタンで入力欄に入れるだけ（保存するまでお客様には出ない）
- 保存は前後の空白を落とす。空にして保存すると NULL（出さない）
- 入力中に「お客様にはこう表示されます」の見本を同じ部品で出す
- 🔴 **特定のジムの文は migration に書かない**（リポジトリは public）
- 列が読めない環境は `tenantColumns.ts` で null に倒す＝出さない
- `TrainerGymSettings.tsx` は行数の上限（1600）に達している。カードは `VisitGuideCards`（来店の目安時刻と2枚まとめた部品）から置いた

## 体験予約ページへの届け方

ログイン不要なので `get_tenant_public` に列を足した（`20261027010000_pre_visit_note.sql`）。
返り値の型が変わるので **DROP → CREATE → GRANT の貼り直し**。列の並びは本番の定義（2026-10-27 の
`pg_get_functiondef`）の末尾に足しただけ。

本番への適用は、同じトランザクションの中で anon と authenticated を演じて読めることを確かめ、
読めなければ取り消す形にした。適用後、GRANT（PUBLIC / anon / authenticated / postgres / service_role）が
適用前と同じで、anon が御所南の行（`pre_visit_note` は null）を読めることを確認した。

## 例文の根拠（2026-10-27 に調べた）

- 運動の1〜4時間前に体重1kgあたり1〜4gの炭水化物（60分を超える運動）— ACSM・米国栄養士会・
  カナダ栄養士会の共同見解（Thomas, Erdman, Burke 2016）が広く引用している目安
- 食べてから運動すると、長時間の有酸素運動の成績が上がる（短時間では差がない）— Aird ら 2018 のメタ分析
- 筋トレでも、45分を超えるセッションで、しかも長く食べていない（8時間以上）ときは、炭水化物を摂ると
  こなせる量が増える — King ら 2022 のメタ分析（Sports Medicine）
- 直前は脂質・食物繊維の多いものを避け、消化のよい炭水化物（おにぎり・バナナ等）— 一般的な指導
- 空腹時の運動は低血糖になりやすい（とくに糖尿病の治療中の人）
