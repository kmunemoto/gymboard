# データの書き出し（CSV）（2026-08-24）

ジムのデータを CSV でダウンロードする機能。**他のジムへ販売するときの導入障壁を下げるのが目的**
（「自分のデータをいつでも持ち出せる」と「乗り換え時に移行できる」）。
オーナー提案のロードマップのフェーズ1-①。

## 出せるもの（5種）

| 種類 | 元テーブル | 主な列 |
|---|---|---|
| 顧客 | tenant_members ＋ profiles | 名前・ふりがな・電話・プラン・在籍状態・入会/休会/退会・起算日 |
| 予約 | bookings | 予約日・時刻・顧客・種別・状態・担当スタッフ・店側メモ・経路 |
| トレーニング記録 | workouts（＋exercises で種目名） | 実施日・顧客・種目・セット・総ボリューム・メモ |
| 測定 | user_measurements | 測定日・顧客・体重・体脂肪率 |
| 入金 | member_payments | 入金日・顧客・金額・種別・支払方法・プラン・メモ |

顧客は **tenant_members を軸**にする（profiles が欠けている人も1行出す＝人数が合わなくならない）。

## 🔴 CSV インジェクション対策（このファイルの一番の要点）

表計算ソフトは `=` `+` `-` `@`（＋タブ・CR）で始まるセルを**数式として解釈する**。
CSV に載るのは**お客様が自分で入力した文字列**（表示名・メモ・体験の回答）なので、
対策が無いと店の人が Excel で開いた瞬間に任意の数式が走る。

対策は「先頭にシングルクォートを足して文字列として読ませる」（`src/lib/csvExport.ts`）。
Excel は表示時に `'` を隠すので、店の人の見た目は変わらない。

**見張りテストは8本**。この分岐を消すと8本とも赤になることを確認済み。

## 置き場所と責務の分け方

| ファイル | 責務 |
|---|---|
| `src/lib/csvExport.ts` | 組み立て（純粋関数）。エスケープ・BOM・CRLF・ファイル名・ダウンロード |
| `src/lib/gymDataExport.ts` | 何を・どの列で出すか。取得クエリと列定義 |
| `src/components/trainer/TrainerDataExport.tsx` | 画面。取得 → toCsv → downloadCsv を繋ぐだけ |

列を足すときは `gymDataExport.ts` だけ触ればよい。

## 決めたこと

- **オーナー限定**。顧客の連絡先も入金も丸ごと出せるので、スタッフ（trainer）には行ごと出さない
- **UTF-8 BOM ＋ CRLF**。BOM が無いと Excel で日本語が全部化ける
- **0件でも見出し行だけのファイルを落とす**。「空だった」と分かるほうが親切
- **ページングで全件取る**（1000行の壁）。CSV は「全部出せる」ことが価値なので途中で切らない
- 🔴 **取得はすべて `tenant_id` で絞る**。RLS も絞っているが二重で防ぐ
  （migrations 側の穴を1つ踏んだだけで他ジムのデータが混ざる。取り返しがつかない）。
  見張りテストが「すべての `.from()` に `.eq("tenant_id", tenantId)` がある」ことを固定している

## ⚠️ ネイティブではダウンロードできない

iOS/Android の WebView は `<a download>` を無視するため、**アプリからは保存できない**。
`@capacitor/filesystem` を入れれば可能だが、プラグイン追加＝ネイティブの作り直しが要る。

いまは `isNative()` で判定して**ボタンを無効化し、ブラウザで開くよう案内**している。
実運用でも「顧客一覧を Excel で開く」のはパソコンでの作業なので、Web 優先で問題ないと判断した。
ネイティブ保存が要るようになったらプラグイン追加を検討する。
