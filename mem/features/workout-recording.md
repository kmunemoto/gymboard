# ワークアウト記録（トレーナー入力・顧客閲覧）

## 全体像
- 記録の**新規入力はトレーナーのみ**（`TrainerClientDetail.tsx` の記録タブ）。
  顧客は閲覧＋自分の記録の編集（`WorkoutEditModal`）のみ。
- `workouts` 1行 = 1種目/1日。`sets` は JSON（`[{set, weight, reps}]`）。旧形式は
  行直下の `weight`/`reps` のみの場合があり、読み出し側は常に両対応する
  （`recordSets()` / 各所の `w.sets || (w.weight != null ? [...] : [])` フォールバック）。
- 種目マスタは `exercises`（`muscle_group`・`default_sets/reps/weight` あり、動画URL列は無し）。

## 前回値プレフィルと前回メニュー読み込み（2026-07、Hevy等の記録アプリ調査より）
トレーナーのセッション中の入力を速くするための機能。`TrainerClientDetail.tsx`:
- **種目選択時のプレフィル**: `handleSelectExercise` は、フォームが空のときに限り
  「このお客様の直近の同種目の記録」(`findPrevRecord`) をセット構成ごと下敷きにする。
  無ければ従来どおり種目マスタの既定値。**編集モード中は編集対象の行を『前回』として
  拾わない**（`editingRecordIds` で除外）。
- **前回参考表示**: 種目セレクトの下に「前回 7/10: 50kg × 10回・3セット」
  （トップセット＝最大重量のセット）を小さく表示。負荷調整の比較用。
- **前回メニュー読み込み**: 新規入力時のみ表示のボタン（`loadLastMenu`）。直近の記録日
  （`sortedDates[0]`）の全種目・全セットをフォームへ丸ごと展開する。編集モードでは
  非表示（`openEdit` と役割が被り、編集対象を上書きすると混乱するため）。

## 推定1RM・自己ベスト（顧客の記録タブ `CustomerTraining.tsx`）
- **Epley式** `weight × (1 + reps/30)`（1回挙上はそのまま）で、セッションごとの
  トップセットから推定1RMを計算。種目セレクトの下に「推定MAX（直近）」と
  「自己ベスト」を表示し、直近が過去ベストを上回ったら「更新！」バッジを出す。
- 計算のみでDB変更なし。**重量0（自重系）は表示対象外**（推定値が0以下なら非表示）。

## 落とし穴
- `sets` JSON と旧形式（行直下 weight/reps）の両対応を崩さないこと。
- 記録に関わる新機能は「トレーナーが入力する」前提を保つこと（顧客に入力を開放する
  場合は RLS（workouts の INSERT ポリシー）から見直しが必要）。
- 調査メモ: Hevy/バーンフィット/Strong との機能比較で、見送った候補は
  部位サイズ記録（measurements への列追加が必要）・種目フォーム動画リンク
  （exercises への列追加が必要）・セット間休憩タイマー・Apple Watch連携。
  必要になったらこの順で検討する。
