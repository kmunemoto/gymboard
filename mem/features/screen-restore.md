# アプリに戻るとホームに戻る件／開いていた画面を戻す（2026-09-24）

## 要望

宗本さん（画面録画を添えて）:

> ジムボードの予約画面を開いていて、他の所に飛んでジムボードに帰ってきたら
> ホーム画面に帰ってしまうのを直して。ちゃんと開いていたページを保持できてるように。

## 何が起きていたか

録画（7秒）を1秒2枚で切り出して確認した:

1. 会員アプリの予約画面
2. アプリ切り替え → ブラウザで YouTube（**約2秒**）
3. ジムボードに戻る → **GBのロゴ** → ホーム

### 🔴 本当の原因: `src/pages/Index.tsx` が戻るたびに画面を作り直していた

宗本さん「僕だけではなく、みんなこの現象になってます」で、端末の事情ではなく
**毎回決まって起きる**ものだと分かり、辿り直した。

1. Supabase（auth-js 2.108）は、画面が隠れた→見えたのたびに `_recoverAndRefresh()` で
   ログインを確かめ直し、有効なら**毎回 `SIGNED_IN` を通知する**（新しい session オブジェクトで）
2. `AuthContext` は通知ごとに `setUser(session.user)` する＝**同じ人の新しいオブジェクト**。
   `loading` は「別の人になったとき」しか立てないので、ここは正しい
3. ところが `Index.tsx` の所属の確認が `useEffect(…, [user, loading])` で走っていた。
   オブジェクトが替われば走る → `status` が `"checking"` に戻る →
   **全画面の読み込み表示（GBのロゴ）に切り替わる** → `CustomerView` / `TrainerView` が外れる
4. 確認が終わって作り直された画面は `useState("home")` から始まる → **必ずホーム**

お客様・店とも、全員・毎回起きていた。直し方は `user.id` で走らせるだけ
（同じ人なら確かめ直さない）。別の人に替わったときに前の人の結果で上書きしないよう、
`cancelled` の見張りも付けた。

### ⚠️ 最初に読み違えたこと（同じ間違いをしないために）

最初は「GBのロゴ＝ネイティブの起動画面＝iOS がアプリを終了させて起動し直した」と判断し、
「アプリ内の読み込み表示はダンベルの絵」と書いた。**誤り。** `DumbbellLoader` は名前が
古いだけで、いまはアプリのアイコン（GBのロゴ）を描いている（ファイル冒頭に経緯）。
**ロゴが出た＝起動し直した、とは決められない。**

また「`AuthContext` が同じ人なら読み込み中にしないので、ログインの確かめ直しは原因ではない」
とも書いたが、それは AuthContext の中だけを見た話で、`user` を依存にしている**下流**
（Index）を見ていなかった。**オブジェクトが替わる通知は、依存に入れている全員を見る。**

## 画面の保存（このメモの本題）は、起動し直したときの備えとして残す

本当にアプリが起動し直すことはある（iOS がメモリのために裏のアプリを終了させる、
ブラウザ版の再読み込み、Service Worker の更新で読み込み直す）。そのときは
開いていたタブが React のメモリにしか無いので、やはりホームに戻る。
**起動し直しは止められないので、覚えておいて戻す。**

## 直し方

**止められないなら、覚えておいて戻す。**

- 規則: `src/lib/screenRestore.ts`（純粋な関数だけ）
- 読み書き: `src/hooks/useScreenMemory.ts`（`useRestoredScreen` / `useRememberScreen`）
- 使っている所: `CustomerView`（タブ）、`TrainerView`（タブ＋開いていたカルテ）

| | |
|---|---|
| 戻す | タブ（お客様・店とも）、店が開いていたカルテ（どのお客様か） |
| 戻さない | 入力の途中（選んだ枠・オプション・事前アンケート）、スクロール位置 |

入力の途中を戻さないのは、離れている間に空きが変わるため。

### 🔴 戻すのは「離れてから30分以内」だけ

翌朝アプリを開いたら昨日の画面、にはしない（ホームには今日の予定がある）。
時刻は**裏に回った瞬間**に書き直す（`visibilitychange` / `pagehide` / Capacitor の `pause`）。
画面を開いた時刻で数えると、予約画面を1時間開いたまま離れた人が戻らなくなる。

### 🔴 URL に行き先があるときは戻さない

`?tab=` / `?billing=`（店の決済の戻り）/ `?checkout=`（会員の購入の戻り）があるときは、
覚えていた画面を被せない。被せると完了の案内が出る画面に着かない。

### 🔴 機能フラグで塞いだタブは戻さない

`CustomerView` は塞いだタブの中身を描かないので、戻すと**真っ白な画面**になる。
このリポジトリでは4つとも ON だが、業種別の兄弟アプリでは OFF にしている
（`src/test/screenRestoreFlags.test.ts` がフラグを OFF にして確かめている）。

### 🔴 端末の保存に失敗しても画面は壊さない

読めない・書けない・壊れている、はすべて「ホームから始める」（今まで通り）に倒す。

### 保存の鍵は役割と利用者ごと

`gymboard.screen.v1.{customer|trainer}.{user_id}`。同じ端末で別の人がログインしても、
前の人が開いていた画面やカルテを引き継がない。

### タブの一覧を lib に置いた

保存してあった値が本物のタブかを実行時に確かめるため、型だけでなく値の一覧が要る。
`src/lib/customerTabs.ts`（新規）と `src/lib/trainerTabs.ts`（`TRAINER_TABS` を追加）。
型は一覧から作るので2つがズレない。テストが「一覧の全タブを画面が描いている」ことも見ている。

## 見張り

- `src/test/indexResume.test.tsx`（4件）: **主因のほう**。同じ人の新しい `user` を渡し直しても
  画面が外れない・所属を確かめ直さない（お客様・店）、別の人なら確かめ直す、
  依存が `[userId, loading]` であること（コメントを落としてから見る）。
  `[user, loading]` に戻すと3件が赤になることを確認済み
- `src/test/screenRestore.test.tsx`（28件）: 録画の流れそのもの（予約画面 → 裏へ →
  終了 → 2秒後に起動 → 予約画面）をフックで再現している
- `src/test/screenRestoreFlags.test.ts`（1件）: フラグ OFF のとき

変異7件（裏に回ったときに書き直さない／30分の期限を外す／URL の行き先を無視する／
読み込みを try で包まない／お客様側を useState("home") に戻す／カルテを全タブで覚える／
塞いだタブを戻す）がすべて赤になることを確認済み。

## 残っていること

- **ネイティブアプリに届くのは iOS のビルドから**（Publish はブラウザだけ）
- 別件で見つけたもの: 利用期間のお知らせ通知（`push-period-reminder`）が `url: "/booking"` を
  送っているが、そのページは存在しない。タップすると「ページが見つかりません」になる
