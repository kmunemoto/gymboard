# 受付しない時間帯（booking_blocked_windows・GB006）（2026-08-21）

「平日は **18:15 の回と 19:30 の回だけを残し、その間に始まる予約を受け付けない**」
のように、開始時刻を揃えて枠数を確保するための帯。

## なぜ必要か（Salute御所南で実際に起きた）

予約は 60分セッション＋間隔15分＝1件が75分を占有する。誰かが 19:00 に取ると
19:00–20:15 が埋まり、**前の枠は 17:45 開始が最後（早すぎる）・次は 20:15 開始
（遅すぎる）**で、その1件が夜を実質1枠に潰す。開始時刻を 18:15 と 19:30 に
揃えれば、18:15 の回の解放（19:15＋15分）ちょうどに 19:30 の回が始まり、
**隙間ゼロで夜が必ず2枠**になる。

回数の制限（GB003）では表現できない（「回数」ではなく「開始時刻の位置」の問題。
max_bookings=0 は CHECK で意図的に禁止している）。

## 🔴 帯は**開区間 (start, end)** —— 両端ちょうどの開始は受け付ける

両端こそが「残したい2枠」そのもの。18:15〜19:30 の帯は 18:30〜19:15 開始を塞ぎ、
18:15 開始と 19:30 開始は取れる。閉区間にすると店は残したい枠自体を塞ぐ。

**時間帯の区間規則は3機能で意味により使い分けている**（テストが3つとも固定）:

| 機能 | 区間 | 意味 |
|---|---|---|
| 容量の帯（booking_capacity_windows） | [start, end) 半開 | スタッフが居る期間 |
| 回数の制限（booking_frequency_limits） | [start, end] 閉 | 制限する開始時刻の範囲（店の「〜19:00」=19:00の回まで） |
| **受付しない帯（この表）** | **(start, end) 開** | **残す2枠の「間」** |

設定 UI の時刻は **15分刻み**（他の帯は30分刻み。ここだけ 18:15/19:30 のような
実際の枠に合わせる必要がある）。行ごとに「{start} と {end} ちょうどに始まる予約は
受け付けます」のヒントを出す（誤解がいちばん起きる場所）。

## 🔴 効くのは自己予約だけ・免除は帯より強い

- トリガー（guard_booking_blocked_window）は auth.uid() = NEW.user_id だけを見る。
  **店側の代理予約は帯の中でも入れられる**（GB003/GB004 と同じ非対称。店の裁量）
- **免除（booking_frequency_limits.exempt、閉区間）に当たるお客様は帯の中でも取れる**
  （「免除は制限より強い」の原則をここにも通した）
- 体験・ドロップイン（trial_bookings）には付けない（GB003 と同じ判断。ゲストに
  会員概念が無い。帯の中に体験が入る事故が実害になったら trial 側の付与を検討）
- 'キャンセル済み' からの復活は日時不変でも判定（バイパス封じ。GB003 と同じ）

## 🔴 旧アプリとの互換のため回数制限の表に相乗りしない

「0回まで」として booking_frequency_limits に載せる案は、**公開済みクライアント
（閉区間で判定）が残したい両端の枠までグレーにする**。別の表なら旧アプリは
読まない＝画面は従来どおりで、DB のトリガーだけが塞ぐ（押すと GB006 エラー。
旧アプリでは汎用文言）。新アプリは枠を「受付外」表示にし、空き待ちの対象からも
外す（待っても取れない）。

## SQLSTATE は GB006

| コード | 意味 | お客様への案内 |
|---|---|---|
| GB003 | 時間帯の回数上限 | 別の時間帯なら取れる |
| GB006 | **受付しない時間帯** | **この時間はそもそも受け付けていない**（前後の時間へ） |

クライアントの検出は `isBlockedWindowError`（src/lib/bookingBlockedWindows.ts）。
文言では判定しない。

## ⚠️ delete_my_gym で実際に踏んだ事故

再定義を **20260821020000 から写して、20260821030000 が足した
booking_capacity_windows の DELETE を落とした**。見張りテスト
（「最後の定義がこの表も消す」）が捕まえた。**必ず直前（最新）の定義から写す**こと。
この表の見張りテストは「新表の DELETE」と「既存表の DELETE が残っていること」の
両方を見ている。

## Salute御所南の運用（2026-08-21 の決定）

- **週1回ルール（平日18:00〜19:00）は enabled=false で解除**（行は残す。復活は
  設定画面のスイッチで可能）。帯で夜が2枠になるので回数制限は不要という判断
- 帯を1件設定: **平日 18:15〜19:30**（＝18:30〜19:15 開始を受け付けない）
- 既に帯の中にある既存予約（19:00 開始など）はそのまま残る（帯は**新しい開始**を
  塞ぐだけ）。自然に消化されて2枠のグリッドに収束する
