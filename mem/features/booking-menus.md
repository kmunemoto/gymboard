# 予約メニュー（2026-10-28）

## 要望

宗本さん（パーソナルピラティスを始める。ピラティスの先生に来てもらう）:

> お客様用にも、筋トレの予約とピラティスの予約で分けて予約できるようにしてほしい。
> お客さんは、ヨガかマシンピラティスのどっちか（を選べる）。

聞いて決めたこと:

1. ピラティスの時間（先生のシフト）は**ひとまずピラティス専用**。先着順にも変えられるようにする
2. 回数は**今のプランから1回**として数える（お客様は同じ料金で両方受けられる）
3. 1日の上限は**曜日ごとの上限をそのまま**使う（メニューで分けない）
4. 時間は**同じ**（プランの長さ）
5. 体験予約はトレーニングだけ（体験はメニューを持たない）
6. 先生は全員のお客様を見てよい（`mem/features/instructor-staff.md`）

メニューの名前に「パーソナル」は付けない（お客様は分かっている）。

## 形

`supabase/migrations/20261028030000_booking_menus.sql`

```
booking_menus(tenant_id, name, staff_user_id, is_active, sort_order)
bookings.menu_id               → booking_menus（ON DELETE の動作なし＝使われたメニューは消せない）
tenants.menu_staff_hours_exclusive  既定 true（専用）/ false（先着順）
```

- **担当（staff_user_id）のいるメニュー**の予約は、その担当の予約になる（DB の `apply_booking_menu` が当てる）。
  その担当のシフト（`staff_schedules`）の時間だけ取れる（シフト外は今まで通り GB002）
- **担当のいないメニュー**（トレーニング）は今まで通り
- メニューを送ってこない予約（古いアプリ・メニューを選ばない代理予約）は、**担当のいない先頭のメニュー**として記録する。
  担当を選んだ予約には付けない
- お客様の予約画面: メニューが**2つ以上**オンのときだけ「メニュー」の選択が出る（1つなら今まで通り）。
  メニューを使っている店では担当の選択は出さない（担当はメニューで決まる）
- 予定表・お客様の予約一覧・完了のダイアログ・新しい予約の通知（メール・プッシュ）にメニュー名を添える
  （メニューが2つ以上ある店だけ。`menuNameOf`）

画面の判定は `src/lib/bookingMenus.ts`。

## 🔴 担当のいるメニューの時間は、そのメニュー専用

`menu_staff_hours_exclusive = true` のとき、担当のシフトの時間に**担当のいない予約（トレーニング）・体験・ドロップイン**を入れない。

| 誰の予約 | 専用の時間に |
|---|---|
| お客様ご自身（担当のいないメニュー） | **入れない**（GB011） |
| お客様ご自身（担当のいるメニュー） | 入れる（自分の担当の時間。シフトは GB002 が見る） |
| 体験・ドロップイン | **入れない**（文言は満枠と同じ。trial-book / drop-in-book が満枠の案内に振り分ける） |
| 店の代理予約 | 入れる（先生のお休みの日にトレーニングを入れる、など店の裁量） |

- 重なりは「開始＋1枠＋オプション＋**間**」と、シフトの [開始, 終了) で見る（`check_booking_overlap` と同じ占有）。
  間を入れないと、直前のトレーニングの間がピラティスの最初の枠を潰す
  （例: シフト 10:00〜、60分＋間15分の店では、トレーニングは 8:45 開始まで。9:00 開始は 10:15 まで食い込む）
- 🔴 **シフトを1行も持たない担当（＝営業時間どおり）は専用の時間を持たない。**
  持たせると営業時間がまるごと専用になり、トレーニングが1枠も取れなくなる。設定カードが「シフトが未設定」と知らせる
- 担当はジムの現役のスタッフに限る（外したスタッフのシフトが残っていても専用にしない）
- 担当が2人いて時間が重なっても、担当のいるメニューの予約どうしは止めない

### 画面への出し方（担当つきのブロック）

`get_tenant_booked_slots` が、専用の時間を **status='ブロック済み' かつ staff_user_id あり** の行として返す
（普通のブロックは staff_user_id が NULL）。

- お客様の予約画面・担当のいるメニュー … 無視する（`isFootprintBlocked` が担当を決めた予約には数えない）
- お客様の予約画面・担当のいないメニュー … **枠ごと出さない**（`overlapsReservedBlock`）。
  「満枠」と見せると、空くことの無い枠にキャンセル待ちが付く
- 公開の体験ページ・古いアプリ … 普通のブロック（体験は入れない／古いアプリでは選べない）
- 未ログイン（公開ページ）には担当の user_id を返さない

店の予定表（代理予約）は `useAllBookings` を見るので、専用の時間は出ない（店はいつでも入れられる）。

## 設定

ジム設定 → **営業時間・受け入れ枠** → いちばん下の「予約メニュー」（`TrainerBookingMenus`。スタッフのシフトの下）。

- 追加（名前・担当）、名前の変更、オン/オフ、並べ替え、削除
- 🔴 予約に使われたメニューは消せない（外部キー 23503）→ 「オフにすると選べなくなります」と案内する
- 「担当のいるメニューの時間は、そのメニュー専用にする」スイッチ（担当のいるメニューがあるときだけ出す）
- インストラクター（制限付きスタッフ）はメニューを変えられない（RESTRICTIVE。設定画面自体も出ない）
- **1人の担当が複数のメニューを持てる**（宗本さんのジムはヨガとマシンピラティスが同じ先生）。
  シフトはその人の1つを共有する＝専用の時間も共有。同じ時間にヨガとピラティスを両方は入れられない
  （担当の重なり GB001）。スタッフ管理の一覧と先生の「アカウント」画面に担当メニューが出る。
  「シフトが未設定」の知らせは担当ごとに1回（先頭のメニューの行）

### 先生を迎える手順（担当のいるメニューを始めるとき）

1. 先生をインストラクターとして招待する（`mem/features/instructor-staff.md`）
2. スタッフのシフトで、先生の曜日と時間を決める（＝ピラティスの時間）
3. 予約メニューで「ヨガ」「マシンピラティス」の担当を先生にしてオンにする
   （始めるのが先の日付なら、メニューの「開始日」を入れてから今オンにする。下の「開始日」）

先生を招待してからメニューを作るまでの間は、スタッフが2人になるので**お客様の予約画面に担当の選択が出る**
（メニューを使っていない店の今まで通りの動き）。手順 1〜3 は続けて行う。

🔴 **古いアプリ（予約メニューを知らない版）は、メニューを使っている店でも担当の選択を出す**
（スタッフが2人以上なら）。担当のメニューを持つインストラクターを、**そのメニューがすべてオフの間**に
お客様が指名すると、DB が GB002 で断る（`trg_guard_booking_menu_teacher`・2026-10-29）。
古いアプリには「別のトレーナーか別の曜日をお選びください」と出る（GB002＝シフト外は古いアプリも知っている）。
店の代理予約・日時の変更（作り直し）・オーナーの指名・メニューを持たないインストラクターの指名は止めない。
2026-10-29、宗本さんのジムで先生を迎え、ヨガ・マシンピラティスの担当にした（メニューはまだオフ）ときに、
1.8.9 のお客様の予約画面に先生が出て、普通のトレーニングで指名できてしまうことに気づいて足した。

## 開始日（starts_on・2026-10-29）

宗本さん「（マシンピラティスは）今すぐ（オンに）だが、11/25 以降から予約は可能」。
メニューを今オンにして、**開始日以降の日付だけ**を前もって予約できるようにする（NULL はすぐ）。
`supabase/migrations/20261029020000_booking_menu_starts_on.sql`

開始日より前の日付（JST の予約日）は:

| どこ | 動き |
|---|---|
| お客様の予約画面（新しいアプリ） | カレンダーでその日を選べない（`menuStartsOn` → `menuNotStarted`）。チップに「11/25〜」、選ぶと「11/25から予約できます」 |
| DB・新しいアプリの予約 | そのメニューを選んだお客様ご自身の予約を GB012 で断る（`apply_booking_menu`） |
| DB・古いアプリの指名 | その先生を指名したお客様ご自身の予約を GB002 で断る（`guard_booking_menu_teacher`。「その日に予約できるメニュー」が無い先生） |
| 🔴 専用の時間 | **始まる前は専用にしない**（`menu_reserved_overlaps`・`get_tenant_booked_slots`）。始まる前からトレーニング・体験の枠を塞がない |
| 店の代理予約・日時の変更（作り直し） | 止めない |

- 設定: 予約メニューの各行の「開始日」（日付欄。欄を離れたときに保存。「解除」で消す）
- 関数4本は本番の定義に開始日の条件を足しただけ。`src/test/bookingMenuStartsOn.test.tsx` が、
  足した部分を除けば元の定義と1文字も違わないことを見張っている
- 開始日の列が無い環境では列を外して読み直す（`useBookingMenus`）。メニューが読めないと「メニューを
  使っていない店」に戻り、担当の選択（先生の名前）が出てしまうため

## 日時の変更

`rescheduleBooking` は旧行を消して作り直すので、**メニューも引き継ぐ**（渡さないと消える）。
お客様の画面は予約の変更中はメニュー・担当の選択を出さない（変更は元の予約のメニュー・担当のまま）。
外したメニューの予約でも、作り直し（created_via='reschedule'）は通す。

## 既知の穴

- メニューを送らない古いアプリで、担当の選択から先生を選んで入れた予約は menu_id が NULL のまま
  （ヨガかピラティスか分からないので当てない）。予定表には先生の名前だけが出る。
  通るのは先生のメニューが1つ以上オンのときだけ（全部オフなら GB002 で断る・上の「先生を迎える手順」）
- キャンセル待ちはメニューを持たない。新しいアプリはピラティスの時間の枠をトレーニングの画面に出さないので
  待つことは無いが、古いアプリでは「満枠」に見えるので待てる（ピラティスのキャンセルで「空きました」が届くが、
  開くと取れない）
