# 全兄弟アプリへ: 「リリースノート書いて」＝ リリース完了の合図

2026-08-05 に宗本さんが決めた取り決めです。**全アプリ共通。**

---

## 取り決め

> 僕がリリースノート書いてと言ったら、もうそこまでのバージョンはリリースしたんだな、と
> 理解してください。**わざわざリリースし終わったことを報告しないので。**

**これがリリース完了を知る唯一の信号です。** 他に通知は来ません。

---

## なぜこれが要るのか

ストアへの提出は宗本さんが手で行います。**セッションからは確認する手段がありません。**

- iOS … Actions はアップロードまで。審査・公開は人の操作
- Android … Windows + Android Studio で署名 → Play Console へ手でアップロード
- **`android/` は `.gitignore` 済み**なので、実際に出た版数はリポジトリから読めない
- クラウドセッションからは Play Console も App Store Connect も見られない

上流では実際に、**`versionCode` の現在値が分からず版を上げようがない**という事故が
起きた。毎回「リリースしましたか？」と聞くのは宗本さんの手間が増えるだけなので、
**依頼そのものを信号にする**ことで確認のやり取りを無くす。

---

## 言われたらやること

`リリースノート書いて` と言われたら、**文章を書く前に**版数を進める。

```
1. リリース実績の記録に、いま出ていた版を実績として書く
2. 次に出す版数を1つ進める（versionCode +1 / versionName 更新）
3. iOS 側のバージョン表記も更新する
4. そのうえで新しい版のリリースノートを書く
```

**「リリースしましたか？」と聞き返さない。** 聞かなくても分かるようにこの取り決めがある。

### 版を上げるか迷ったとき

**同じ版のノートを直したいだけ**の依頼もある（内容の追記・訂正など）。
直前のやり取りが同じ版についてなら、版は上げない。

判断がつかないときは **上げる方を選ぶ。**

| | 起きること |
|---|---|
| 余分に上げた | `versionCode` が1つ飛ぶだけ。**害はない**（単調増加でありさえすればよい） |
| 上げ足りなかった | Play が `Version code N has already been used` で弾く。**ビルドし直し** |

---

## 版数の現在値を、リポジトリに持っているか

この取り決めが機能する前提として、**「次に出す版数」がリポジトリから読める**必要がある。

このリポジトリ（ジムボード）は 2026-08-05 に `android-version.json` を作った。
それ以前は `android/app/build.gradle`（`.gitignore` 済み）を手で書き換えていたため、
**現在値がどこからも読めなかった。**

そのせいで:

- 「バージョンを1つ上げて」と言われても**上げようがない**（実際にそうなった）
- `npx cap add android` で作り直すと Capacitor 既定値（`versionCode 1` / `"1.0"`）に戻る
- 上げ忘れも上げたつもりも、**Play にアップロードするまで気づけない**

**持っていないなら作ること。** このリポジトリの実装（PR #268）:

| ファイル | 役割 |
|---|---|
| `android-version.json` | `{ "versionCode": 82, "versionName": "9.1" }`。**唯一の記録** |
| `scripts/set-android-version.mjs` | それを `android/app/build.gradle` に書き込む |
| `scripts/build-android.bat` | 手順の最後で上記を呼ぶ |
| `src/test/androidVersion.test.ts` | 実際にスクリプトを走らせて検証（17件） |

これで「バージョンを上げた」が**コミットとして履歴に残る**
（iOS が `ios-build.yml` に `MARKETING_VERSION` を直書きしているのと同じ発想）。

### CI を使っているアプリは採番の線に注意

このリポジトリは手作業側が 82 から1ずつ、Android CI を使うアプリ（ストレッチボード等）は
`BASE(10000) + run_number` のように、**ぶつからない採番にする**（テストで見張る）。

このリポジトリの `android-build.yml` は作ってあるが CI 経路としては使っていない
（手作業のまま）。CI 経路のアプリでは `versionCode` が `github.run_number` から
自動導出され、手作業のような「上げ忘れ」自体が構造的に起きない。その場合でも
`versionName` は自動で決まらず入力が必要になるので、そちらは**別途トラッキングする値**
として repo に持つこと（詳細は各アプリの `mem/features/android-ci.md` 相当）。

---

## それでもストアが正である

この取り決めは「聞かなくて済む」ようにするもので、**実態と自動同期はしない。**

記録の取りこぼしや依頼の行き違いはありえる。
**アップロード直前に Play Console / App Store Connect の最新版数を必ず確認すること。**

`set-android-version.mjs` は、既存の `build.gradle` より下げようとしたときに
警告を出すが、**Play に上がっている値までは見に行けない。**

---

## まとめ

```
「リリースノート書いて」
  → 前の版はもう出ている
  → 実績を記録し、版数を1つ進めてから、ノートを書く
  → 「リリースしましたか？」とは聞かない

迷ったら版は上げる（飛ぶのは無害・足りないのは弾かれる）
アップロード前にストアの実物を確認する
```
