# お店のデータを CSV で書き出せるようにしてください

ジムボード（このアプリの元）で 2026-08-24 に実装・本番稼働済みの機能です。
出せる種類・列はこのアプリの現物に合わせて読み替えてください。

## 出せるもの

このアプリにあるものを出す。ジムボードは5種（顧客・予約・記録・測定・入金）だが、
**機能フラグで切ってあるもの（記録・測定など）は最初から対象外**にしてよい。
最低限は **顧客・予約** の2種。

🔴 **顧客は「在籍テーブル」を軸にする**（プロフィールを軸にしない）。
プロフィールが欠けている人も1行出るので、**人数が合わなくならない**。

## 🔴 CSV インジェクション対策（このファイルの一番の要点）

表計算ソフトは `=` `+` `-` `@`（＋タブ・CR）で始まるセルを**数式として解釈する**。
CSV に載るのは**お客様が自分で入力した文字列**（表示名・メモ・回答）なので、
対策が無いと**店の人が Excel で開いた瞬間に任意の数式が走る**。

対策は「先頭にシングルクォートを足して文字列として読ませる」。Excel は表示時に `'` を
隠すので、店の人の見た目は変わらない。**見張りテストを付けて、この分岐を消したら赤になる
ことまで確認する**（ジムボードは8本）。

## 決めたこと（変えないこと）

- **オーナー限定**。連絡先も入金も丸ごと出せるので、一般のスタッフには行ごと出さない
- **UTF-8 BOM ＋ CRLF**。🔴 BOM が無いと Excel で日本語が全部化ける
- **0件でも見出し行だけのファイルを落とす**。「空だった」と分かるほうが親切
- **ページングで全件取る**（1000行の壁）。CSV は「全部出せる」ことが価値なので途中で切らない

## 置き場所（責務を3つに割る）

| 層 | 責務 |
|---|---|
| 組み立て（純粋関数） | エスケープ・BOM・CRLF・ファイル名・ダウンロード |
| 定義 | 何を・どの列で出すか。取得クエリと列定義 |
| 画面 | 取得 → 組み立て → ダウンロード を繋ぐだけ |

列を足すときに触るのは真ん中だけ、という形にする。

## 🔴 出したその日から壊れていた: 「絞りすぎて空になる」向きを見張っていなかった

ジムボードで実際に起きたこと。**本番で顧客CSVの中身がほぼ空欄だった。**

| お店 | 顧客数 | 名前・電話・プラン等が空欄 |
|---|---|---|
| A店 | 38 | **37** |
| B店 | 16 | 1 |

### なぜ

プロフィール表に生えていた `tenant_id` 列が、**誰も埋めていない列**だった（本番71行中55行が
NULL）。在籍の正は在籍テーブルのほうで、テナント解決の関数も全部そちらを読む。
`profiles.tenant_id` を読んでいたのは**実質この書き出しだけ**だった。

埋まらない理由は書き込みの順序で、プロフィールを upsert する時点ではまだ所属が確定していない。

### 気づけなかった理由（ここが本題）

**書き出しは成功し、行数も人数と一致する。** 顧客一覧は在籍テーブルを軸に作り、プロフィールが
無い人は null で埋めるフォールバックがあるので、「38人ぶん出た。中身が空なだけ」という形に
なる。**エラーもログも出ない。**

そして見張りテストは「`tenant_id` の絞りを消したら赤」を固定していた。つまり
**絞りが効きすぎて0件になる向きは1つも見ていなかった。片側しか見ていない見張りだった。**

### 直し方

プロフィールを `tenant_id` で絞るのをやめ、**テナントで絞り込んだ行から出てきた顧客ID**で引く。

- 顧客CSV … 在籍テーブル（テナントで絞り済み）の user_id で引く
- 他のCSVの「顧客名」列 … これから出す行に実際に出てくる user_id で引く

ID の出所が既にテナント境界を通っているので、**絞りとしてはこちらのほうが強い**。
`.in()` は URL に載るので 200件ずつ分割すること。

### 見張りは両方向に置く

- プロフィールを `tenant_id` で絞ったら赤（**空欄バグの再発**）
- プロフィール以外は `tenant_id` の絞りが必須（**他店混入**）
- 取得は共通ヘルパを通す（生の select を散らさない）

🔴 **このアプリでも先に確認すること**: `profiles.tenant_id` に相当する列があるか、
あるなら実際に埋まっているか。`SELECT count(*) FILTER (WHERE tenant_id IS NULL)` を
本番で1回数えるだけで分かる。**CSV 機能を入れないとしても、この列を読んでいる箇所が
他に無いか grep する価値がある。**

## 🔴 取得はすべてテナントで絞る（二重防御）

RLS も絞っているが、画面側でも必ず絞る。migrations 側の穴を1つ踏んだだけで
他店のデータが混ざり、**取り返しがつかない**。
見張りテストで「すべての取得にテナントの絞りがある」ことを固定する。

## ⚠️ ネイティブアプリではダウンロードできない

iOS/Android の WebView は `<a download>` を無視するため、**アプリからは保存できない**。
ファイルシステムのプラグインを入れれば可能だが、プラグイン追加＝ネイティブの作り直しが要る。

ジムボードは**ネイティブ判定でボタンを無効化し、ブラウザで開くよう案内**している。
実運用でも「一覧を Excel で開く」のはパソコンでの作業なので、Web 優先で問題ないと判断した。

## ついでに点検する価値があるもの

ジムボードはこの作業のついでに `index.html` に残っていた Lovable 由来のメタタグ
