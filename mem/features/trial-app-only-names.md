# 体験予約サイトから「アプリでご予約ください」へ案内する（店ごと）

2026-09-19 宗本さんの要望（要旨）:

> すでにうちの会員で、ジムボードのアカウントも持っている方が、
> 体験予約サイト（`/trial`）から予約してしまう。直接は言いにくいので、
> **体験予約サイトからは予約できないようにして、アプリから予約するよう案内を出したい。**
> **これは私のジムだけ。予約システムには影響を与えず、指定した単語並びのみを弾く。**

---

## 🔴 お名前は**リポジトリに1文字も書かない**

このリポジトリは **public**。単語をコードに書けば実名がインターネットに公開される。
コミットメッセージは `.gitignore` できないし、squash-merge 運用では履歴の書き換えも現実的でない。
（2026-08-08 に Apple のクライアントシークレットで同じ轍を踏んでいる）

さらに **判定を画面側でやるのも駄目**。単語リストをブラウザへ送る＝開発者ツールで誰でも読める。
体験予約ページは**未ログインの公開ページ**なので、「見えるのは店の人だけ」が成立しない。

そこで置き場をこう分けた:

| 何 | どこ | 誰が読めるか |
|---|---|---|
| 単語そのもの | `tenants.trial_app_only_names`（`text[]`・既定 `{}`） | その店のオーナー／スタッフだけ（`tenants` の RLS） |
| 判定 | `trial_name_needs_app(tenant, name)` → **boolean だけ** | anon（公開ページ） |
| 公開ページへの受け渡し | **しない**（`get_tenant_public` には足さない） | — |

🔴 **`get_tenant_public` にこの列を足さないこと。** 足した瞬間、体験予約ページを開いた
全員がリストを読める。`src/test/trialAppOnlyNames.test.ts` が
**全 migration の `get_tenant_public` の定義**を走査して見張っている
（ファイル全体を見ると `COMMENT ON COLUMN` の説明文に当たって空振りするので、
関数定義だけを切り出して見ている）。

---

## 判定のしかた

`normalize_name_for_match()` で揃えてから **部分一致**（`strpos`）:

```
NFKC（全角/半角・半角カナ・全角スペース）→ 空白と「・」を除去
→ ひらがな→カタカナ（translate の対応表）→ 小文字化
```

本番で確認済み: `'ﾔﾏ ﾀﾞ　たろう・Ａ'` → `'ヤマダタロウa'`。

部分一致なので **姓だけ登録すれば姓名で書かれても当たる**。逆に
**短い単語ほど広く当たる**ので、よくある姓やカタカナ2〜3文字は
無関係の新規のお客様まで案内してしまう（設定画面にもそう書いてある）。

🔴 **空文字・空白だけの単語を1つでも入れると全員が当たる**（正規化後が空 →
`strpos` が必ず 1）。DB 側（`normalize_name_for_match(kw) <> ''`）と
画面側（`if (!word) return;`）の**両方**で弾いている。

## 二重に止めている（案内と、実際の拒否）

| | どこ | 役割 |
|---|---|---|
| 案内 | `TrialBooking.tsx` の `handleSubmit`（送信の直前に RPC） | 予約を作らず `TrialAppOnlyDialog` を出す |
| 拒否 | `trial_bookings` の `enforce_trial_app_only_names`（BEFORE INSERT） | 画面を迂回されても入らない |

**画面だけだと「案内は出るが予約は入る」**（送信は誰でも組み立てられる）。
**DB だけだと**お客様には `trial-book` の汎用エラー（500）しか見えず、打つ手が分からない。

### 🔴 どちらも「判定できなければ通す」

- 画面: `if (!nameErr && needsApp === true)` … 通信の失敗で新規のお客様を断らない
- DB: `EXCEPTION WHEN OTHERS THEN RETURN NEW` … この機能のために予約を1件も落とさない

⚠️ 拒否の文面に **「この時間帯」を入れないこと**。`trial-book/index.ts` は
insert のエラー文に「この時間帯」が入っていると `slot_taken` と判定し、
「別の時間をお選びください」と案内してしまう（アプリへの案内にならない）。

## 効く範囲（「予約システムに影響を与えない」の中身）

| | どうなるか |
|---|---|
| 体験予約（`/trial`・`booking_kind = 'trial'`） | **ここだけ効く** |
| ドロップイン（同じ `trial_bookings` に同居） | 効かない（`booking_kind` で除外） |
| 会員の予約（`bookings`） | 効かない（トリガーを `bookings` に付けていない） |
| 店の代理予約 | 効かない |
| 単語が0件の店（既定） | **何も起きない**。RPC は必ず false |

## 置き場

| 何 | どこ |
|---|---|
| 設定列 | `tenants.trial_app_only_names`（`text[] NOT NULL DEFAULT '{}'`） |
| 正規化 | `normalize_name_for_match(text)` |
| 判定 | `trial_name_needs_app(uuid, text)` → boolean（`anon` に GRANT） |
| 最後の砦 | `enforce_trial_app_only_names()` + `trial_bookings` の BEFORE INSERT |
| 画面（お客様） | `src/pages/TrialBooking.tsx` / `src/components/booking/TrialAppOnlyDialog.tsx` |
| 画面（店） | `src/components/trainer/TrialAppOnlyNamesCard.tsx`（ジム設定 → 体験予約） |

案内先のストアURLは `src/lib/brand.ts` の `STORE_URLS`（アプリ更新のお願いと同じもの）。
**URL が空のフォークではそのボタンを出さない**（押しても何も起きないボタンを作らない）。

ダイアログは**必ず閉じられる**。同姓・人違いのときに詰ませないため
（`AppUpdateDialog` と同じ考え方）。

## 本番へ適用した記録（2026-09-19）

3段構え。**8パターンすべて設計どおり**（`RAISE EXCEPTION` で全部ロールバック済み）。

```
1. 読み取り  col_exists=0 / rpc_exists=0 / trigger 無し（未適用）
2. 適用      列 + normalize_name_for_match + trial_name_needs_app(+GRANT) + トリガー
3. 実測（未来日に実際に INSERT を試す。単語は検査用のダミー）
   (A) 体験 x 該当              = REJECTED   ← 効いている
   (B) 体験 x 該当(かな/空白)   = REJECTED   ← 正規化が効いている
   (C) 体験 x 無関係（対照）    = ACCEPTED
   (D) ドロップイン x 該当（対照）= ACCEPTED
   (E) 他店 x 該当（対照）      = ACCEPTED   ← 他店に効いていない
   (F) anon で RPC             = 該当 true / 無関係 false
   (G) anon で tenants を直読み = 0 行       ← リストは読めない
   後始末  probe の行は0件・フラグは全20テナント空のまま
```

そのうえで **Salute御所南にだけ** 単語を4つ登録した（2026-09-19）。
他19テナントは空のまま＝挙動は1ミリも変わっていない。

🔴 **登録した単語そのものはここには書かない。** 見るときは本番か、
アプリの **ジム設定 → 体験予約 →「体験予約サイトからアプリへご案内する方」**。
足す・消すのは宗本さんが画面からできる（こちらに頼む必要はない）。

## 番人（`src/test/trialAppOnlyNames.test.ts`・29件）

変異9パターンが赤になることを確認済み:

| 変異 | 何が起きる実装か |
|---|---|
| 空単語を無視する条件を外す | **全員**がアプリへの案内になる |
| トリガーを `bookings` に付け替える | 会員の予約まで止まる |
| ドロップインの除外を外す | 訪日客の当日利用まで止まる |
| 判定が落ちたら通す、を外す | 判定のバグが全店の体験予約を止める |
| 断りの文面に「この時間帯」を混ぜる | 満枠と誤判定され「別の時間を」と案内される |
| `anon` への GRANT を消す | 公開ページが判定を呼べない（案内が出ない） |
| `get_tenant_public` に列を足す | **単語リストが全世界に公開される** |
| 画面の判定を「読めなければ弾く」に倒す | 通信の失敗で新規のお客様が予約できない |
| 案内を出しても送信を続ける | 案内は出るのに予約も入る |

### ⚠️ 番人を書くときの罠（通算6回目）

このファイルは**コメントに「この時間帯」と書いてある**（そう書くなという注意書き）。
素の `toContain` だと**実コードを1行も見ないままコメントに当たる**。
`stripComments` を通すこと。`COMMENT ON COLUMN` の**文字列リテラル**は
`--` ではないので落ちない点にも注意（`get_tenant_public` の検査で実際に踏んだ。
関数定義だけを切り出して見るように直した）。

## やっていないこと（必要になったら）

- **会員かどうかの自動判定**（メールアドレスで `profiles` を引く等）。
  体験予約は未ログインで、名前もメールも自己申告。家族の代理申込みもあるので、
  自動で結び付けると**本物の新規を断る**ほうが起きやすい。いまは店が名指しで登録する形。
- **アプリ側から「体験ではなく通常予約を」と誘導する導線**（いまはストアを開くだけ）
- 該当したことを店に通知する（誰がいつ案内されたかは残していない）
